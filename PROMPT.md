Привет. Я передаю тебе готовый рабочий проект — планировщик поездки «Вуокса-2026 · сборный лист».
Это **не макет и не черновик**: приложение работает, им уже пользуются. Твоя задача — продолжать его,
а не переписывать с нуля.

**Сначала прочитай `README.md` в этой папке целиком.** Там архитектура, модель данных, все формулы расчётов,
права доступа, настройки Supabase, и — важно — список ограничений, которые нельзя нарушать
(один HTML-файл, ванильный ES5, никаких фреймворков и внешних загрузок, всё на русском, мобильный приоритет).

## Что в папке

## Задача 1 — опубликовать на GitHub Pages

Supabase Storage не подходит: он принудительно отдаёт HTML как `text/plain`. База данных в Supabase
остаётся и работает, а страницу нужно раздавать с Pages.

1. Создай публичный репозиторий (предложи имя, например `vuoksa-2026`), положи в корень `index.html`,
   а исходники — в `src/`.
2. Напиши `build.js` на чистом Node без зависимостей: читает `src/`, делает две литеральные подстановки
   и пишет `index.html` и `Вуокса-2026.html`. Литеральная замена, не regexp — в данных есть `$` и суммы.
3. Включи Pages: Settings → Pages → ветка `main`, папка `/ (root)`. Скажи мне итоговую ссылку.
4. Дай мне четыре персональные ссылки: `?u=max`, `?u=kos`, `?u=mis`, `?u=zhe` — я разошлю их в чат.
5. Опиши в `README` репозитория, как обновлять публикацию (`node build.js` + commit + push).

## Задача 2 — заменить опрос на Realtime

Сейчас `src/online.js` опрашивает сервер каждые 4 секунды. Переведи на Supabase Realtime
(`postgres_changes` на таблице `trips`), опрос оставь резервом на случай, когда сокет не поднялся.
Учти ограничение: без npm и без ES-модулей, только `fetch` и `WebSocket` вручную — либо обоснуй,
почему в этом файле допустимо подключить SDK с CDN (для онлайн-версии интернет есть; для офлайн-версии
модуль всё равно вырезается при скачивании).

## Задача 3 — правки по позициям вместо перезаписи документа

Сейчас на сервер уходит весь `S` целиком, и при одновременной правке двумя людьми побеждает последний.
Сделай отправку изменённых позиций (у каждой есть `i` и `ua`) и слияние на стороне сервера или клиента
по той же логике, что уже описана в `README` в разделе «Слияние чужого файла».

## Задача 4 — проверить на живом iPhone

У меня iPhone 13. Ранее скачанный файл открывался белым экраном — причина найдена и исправлена
(в файл попадали служебные скрипты среды сборки, теперь они вычищаются, см. `saveFile` в `README`).
Проверь, что офлайн-файл открывается из «Файлов» и что всё работает: галочки, редактирование текста,
добавление позиций, «Сохранить файл», загрузка чужого файла. Если найдёшь ещё причины — исправь.
