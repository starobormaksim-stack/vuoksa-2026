# Вуокса-2026 · сборный лист — передача в разработку

## Что это

Планировщик подготовки к поездке четырёх друзей с палатками на острова озера Вуокса, 10–14 августа 2026.
Существует в двух видах, собранных из одного исходника:

| Файл | Что это |
|---|---|
| `Вуокса-2026.html` | **офлайн-версия**: один самодостаточный HTML, работает по `file://` без интернета, пересохраняет сам себя вместе с данными |
| `index.html` | **онлайн-версия**: то же самое + модуль синхронизации с Supabase, автопогода, версии на сервере |

**Важно: это не макет, а работающее приложение.** Задача — продолжать его развивать, а не переписывать с нуля.
Весь код — ванильный ES5, без сборщиков, без npm, без фреймворков. Так и должно остаться (см. «Ограничения»).

## Сборка

Исходники в папке `src/`:

```
src/app.template.html   основной файл с плейсхолдерами __SEED__ и __HERO__
src/seed.json           все данные поездки (снаряжение, закупка, логистика, меню, экипаж с фото в base64)
src/hero-b64.txt        обложка (JPEG 1100×1100, base64 data-URL, ~285 КБ)
src/online.js           модуль синхронизации с Supabase (только для онлайн-версии)
```

Сборка — две подстановки строк, без инструментов:

```js
// офлайн
let off = template
  .replaceAll('__SEED__', seedJson)   // литеральная замена, не regexp
  .replaceAll('__HERO__', heroDataUrl);
// онлайн: вставить модуль отдельным скриптом перед закрывающими тегами
const marker = '</script>\n</body>\n</html>';
let on = off.replace(marker, '</script>\n<script id="sync-code">\n' + onlineJs + '\n</script>' + marker.slice('</script>'.length));
on = on.replace('<title>ВУОКСА · 2026</title>', '<title>Вуокса-2026 · сборный лист</title>');
```

Осторожно с `String.replace` и `$` в данных — в JSON есть суммы и символы валют; используйте литеральную замену (`split().join()`).

Размеры: офлайн ≈ 681 КБ, онлайн ≈ 704 КБ. Ограничение, о котором договаривались с заказчиком — до 1,5 МБ.

## Публикация · GitHub Pages

Supabase Storage **не подходит** для раздачи страницы: он принудительно отдаёт HTML как `content-type: text/plain`
(проверено — перезалив с правильным типом не помогает, это их защита от размещения сайтов на домене `supabase.co`).
База данных в Supabase при этом работает и остаётся.

Сделано: репозиторий `starobormaksim-stack/vuoksa-2026`, Pages из ветки `main`, папка `/ (root)`.
Адрес: **https://starobormaksim-stack.github.io/vuoksa-2026/**

### Как обновить публикацию

```bash
node build.js
git add -A
git commit -m "что поменялось"
git push
```

GitHub Pages пересобирает страницу сам, обычно за минуту. Проверить, что новая версия доехала:

```bash
curl -s -o /dev/null -w "%{http_code} %{content_type} %{size_download}\n" https://starobormaksim-stack.github.io/vuoksa-2026/
```

`node build.js` собирает **обе** версии из `src/`, поэтому руками `index.html` и `Вуокса-2026.html` не правят —
правки идут в `src/app.template.html`, `src/online.js`, `src/seed.json`.

### Ссылки для экипажа

Каждому своя, с ключом прав: `?u=<имя латиницей>&k=<ключ>`. Ключ лежит в `S.people[].key` и меняется,
как только владелец меняет человеку права, — старая ссылка перестаёт давать полномочия.
Копировать удобнее из приложения: «Экипаж» → кнопка под фотографией, либо «⋯» → «Ссылки для экипажа»
(и то и другое видит только владелец).

Подтверждённый ключ запоминается в браузере (`localStorage['vuoksa2026.auth']`), поэтому потом можно заходить
и по короткому адресу. Ссылка без ключа или с устаревшим даёт права участника и показывает подсказку
попросить новую.

### Что кому можно в онлайне

| Действие | владелец | редактор | участник |
|---|---|---|---|
| скачать офлайн-копию, вернуть её обратно в онлайн | да | нет | нет |
| видеть и копировать ссылки экипажа | да | нет | нет |
| менять права и состав экипажа | да | да | нет |
| остальное (отметки, цены, тексты, позиции) | да | да | по своим позициям |

В офлайновом файле ограничений нет: он уже на руках, и его правит и пересохраняет кто угодно.

### Что ещё нужно выполнить в SQL Editor — для Realtime

Пока этот блок не выполнен, всё работает, но обновления приходят опросом (раз в 8 секунд), а не мгновенно.

```sql
create table if not exists trip_pings (
  trip_id text primary key,
  updated_at timestamptz not null default now(),
  author text default ''
);
alter table trip_pings enable row level security;
create policy "crew_all_pings" on trip_pings for all using (true) with check (true);
alter publication supabase_realtime add table trip_pings;
```

Подписываемся именно на `trip_pings`, а не на `trips`: документ весит под мегабайт, и гонять его целиком
в каждом событии Realtime накладно (и упирается в лимит размера payload). Клиент после успешной записи
обновляет одну крошечную строку-сигнал, остальные по событию забирают документ обычным `GET`.

### Как работает синхронизация (`src/online.js`)

* весь документ — одна строка `trips` с `id = 'vuoksa2026'`, поле `data jsonb` = целиком состояние `S`;
  `?sandbox=1` в адресе переключает на копию `vuoksa2026-test` — в ней можно проверять что угодно,
  боевые данные не пострадают;
* запись: перехвачена функция `touch()` — после любого изменения дебаунс 900 мс и `pushTry()`:
  читаем текущую строку, вливаем в себя чужие правки (`applyRemote`), пишем `PATCH` с условием
  `updated_at=eq.<та метка, которую видели>`. Если кто-то успел записать раньше, PostgREST вернёт
  пустой массив — цикл повторяется (до 5 попыток). Так одновременная правка двумя людьми
  больше не затирается: раньше побеждал последний, теперь сохраняются оба набора правок;
* чтение: событие Realtime по таблице-сигналу `trip_pings` → `pull()`. Пока событий не приходило,
  опрос каждые 8 с; после первого события — раз в минуту, как страховка. Плюс на `visibilitychange` и `online`;
* Realtime сделан вручную на `WebSocket` (протокол Phoenix, `phx_join` + `heartbeat` раз в 25 с,
  переподключение с нарастающей паузой до 30 с). SDK с CDN сознательно не берём: файл должен остаться
  самодостаточным, а обе версии — собираться из одного исходника;
* разрешение конфликтов: позиции сливаются по `i` и метке `ua` (`mergeInto`), а не «кто последний»;
  новые позиции из зашитого сида домердживаются функцией `mergeSeed`;
* перерисовка откладывается, пока курсор стоит в редактируемом поле, — чужие правки не выдёргивают
  текст из-под руки (`renderSoon`, `editing`);
* индикатор в шапке `#syncBar`: точка + подпись (`ok` зелёный / `work` янтарный / `err` красный / `off` серый);
* версии: `trip_versions` — снимок всего `S` с подписью и автором, список, откат, удаление;
* «Скачать офлайн-копию»: сперва `refreshWeather(true)`, затем штатный `saveFile()`, который вырезает
  из клона `#sync-code` и `#syncBar` (список селекторов в глобальной `SAVE_STRIP`) — в скачанном файле
  нет ни синхронизации, ни ключа Supabase (проверено);
* «Загрузить офлайн-файл в онлайн»: `#fileIn` → регулярка вытаскивает `<script id="seed">` → `mergeFile(inc)`
  → сработавший `touch()` отправляет результат на сервер.

**Что стоит улучшить.** Настоящие права — только через Supabase Auth и RLS по `auth.uid()`. Сейчас ключ в ссылке
разграничивает по-джентльменски: `anon`-ключ лежит в файле, и кто получит чужую ссылку, получит её права.
В скачанном офлайн-файле ключи участников тоже лежат — файл стоит пересылать только своим.

## Автопогода (Open-Meteo, без ключа)

```
геокодинг : https://geocoding-api.open-meteo.com/v1/search?count=1&language=ru&format=json&name=<место>
прогноз   : https://api.open-meteo.com/v1/forecast?latitude=..&longitude=..
            &daily=weathercode,temperature_2m_max,temperature_2m_min,precipitation_probability_max,windspeed_10m_max
            &timezone=auto&start_date=YYYY-MM-DD&end_date=YYYY-MM-DD
```

Место берётся из `S.trip.place` (часть до символа `·`), даты — от `S.trip.start` на `S.weather.days.length` суток.
`weathercode` переводится в русский текст словарём `WX`. Скорость ветра приходит в км/ч — делится на 3,6.
Работает: по «Приозерск» получены координаты 61.04 / 30.14 и реальный прогноз на 10–14 августа.
Если даты дальше горизонта прогноза (~16 суток), API возвращает пустой `daily` — тогда показывается тост
и остаются прежние значения. Колонка «что это значит для нас» — авторский текст, при обновлении сохраняется.

## Модель данных (`S`)

Живёт в `<script id="seed" type="application/json">`, дублируется в `localStorage['vuoksa2026']`
(дебаунс 300 мс, вся работа обёрнута в try/catch — во встроенном браузере Telegram на iOS может быть недоступен;
тогда в шапке появляется янтарная полоска, приложение работает из памяти).

```js
S = {
  v, updatedAt, author, me, theme,
  trip: { title, sub, dates, place, route, start, note, hero, lat, lon },
  tileLabels: [4 подписи денежных плиток],
  secTitles: { <id секции>: {h, sub} },
  people: [ { id, name, ini, color, car, role, desc, photo, perm, slug, key, ua } ],
                                    // perm: chief | editor | member
                                    // slug — имя латиницей для ссылки (Maks, Kostya, Misha, Zhenya)
                                    // key  — ключ прав, меняется при смене perm и гасит старую ссылку
  del: { "<список>:<id позиции>": когда удалили },  // иначе слияние воскресит удалённое
  gearSections: [ {id, t} ],                                            // od lod inv ryb pos lich apt
  gear: [ { i, sec, n, c, o:{<personId>:кол-во}, s:{<personId>:статус 0..4},
            q:{<personId>:'причина'}, by, nw, ua } ],
  buySections: [ {id, t, personal} ],                                   // personal:true — алкоголь, не делится
  buy: [ { i, sec, n, c, q, u, pr, prf, st, b, who, by, nw, ua } ],
  log: { dist, kBack, local, p95, p92, consHonda, consAveo, motoH, motoL,
         sawL, boatDay, boatDays, parkDay, parkDays, cars },
  logNotes: [ {k, t, u, c} ],       // редактируемые подписи параметров, k — ключ в log
  calcRows: [ {k, t} ],             // редактируемые подписи строк расчёта
  canRows:  [ {k, t, c} ],          // канистры
  boat: { t1, c1, t2, c2, warn },   // карточка «Ладоги»
  route: [ { i, n, time, c, done, ua } ],
  weather: { updated, src, days:[ {i, d, wd, day, night, prec, wind, means} ], daylight, concl },
  menu: [ { i, t, sub, done, dishes:[{n, q}] } ],
  ideas: [ { i, n, why, who, done, by, ua } ],
  ui: { tab, me, open:{<ключ группы>:bool} }
}
```

Смысл полей, которые неочевидны:

* `gear.o` — сколько штук везёт каждый участник; матрица как в исходном Excel. Личный список — это фильтр `o[me] > 0`.
* `gear.s` — состояние **у конкретного человека**: `0` не взято, `1` в процессе, `2` есть дома, `3` упаковано, `4` в машине.
  В готовность идёт `>= ST_OK` (3). Константы: `ST_ICON`, `ST_NAME`, `ST_N = 5`, `ST_OK = 3`.
* `gear.q[personId]` — «не могу взять» с причиной; строка получает класс `askRow` (красная линия слева),
  причину видят все, в том числе в общей матрице.
* `buy.pr` — цена по плану, `buy.prf` — фактическая. `buyPrice()` возвращает `prf`, если он больше нуля, иначе `pr`.
  Итоги показывают и план, и факт.
* `buy.st` — `buy` | `has_<personId>` | `ask` | `skip`. В сумму идёт только `buy`.
* `buy.who` — кому поручено купить. `by` — кто позицию создал (для прав на удаление).
* `ua` — метка времени последнего изменения позиции, нужна при слиянии файлов.

## Права

Права считаются через `permOf(p)` → `myPerm()` → `isEditor()` / `isChief()`. В офлайновом файле `permOf`
возвращает `p.perm` как есть. В онлайне модуль синхронизации подменяет `permOf`: полномочия даёт только
подтверждённый ключ из личной ссылки, иначе человек считается участником. `canSaveFile()` в офлайне true
для всех, в онлайне — только для владельца. `canDel(item)` — редактор либо автор позиции (`item.by === S.ui.me`).

| Действие | владелец | редактор | участник |
|---|---|---|---|
| свои статусы, «не могу взять» с причиной | да | да | да |
| добавлять позиции | да | да | да |
| удалять чужие позиции | да | да | нет, только свои |
| цены, количества, описания | да | да | да |
| параметры логистики, маршрут, меню, удаление дней | да | да | нет |
| участники и их права | да | да | нет |
| скачать файл и вернуть его в онлайн | да | нет | нет |
| ссылки экипажа | да | нет | нет |

Роль берётся из выбранного «я» (`S.ui.me`), а в онлайне — из ссылки `?u=<имя латиницей или id>&k=<ключ>`
(`applyUrlUser` + `applyAuth`). Оговорка, о которой заказчик предупреждён: ключ `anon` лежит в файле,
поэтому права «джентльменские» — кто получит чужую ссылку, получит её права. Настоящее разграничение
потребует Supabase Auth и RLS по `auth.uid()`.

## Механика «файл пересохраняет сам себя»

`saveFile()`:

1. `document.documentElement.cloneNode(true)`;
2. в клоне `#app` заменяется заглушкой `<div class="boot">Загружаю сборный лист…</div>`;
3. **вычищается всё чужое** — скрипты, кроме `#app-code` и `#seed`; стили, кроме `#app-css` и `#app-css-hero`;
   `<link rel=stylesheet|preload|modulepreload>`; атрибуты `data-om-id`, `data-cc-id`, `data-dm-ref`, `data-src-ver`;
   `style` и `class` с `<html>`; плюс селекторы из `SAVE_STRIP`;
4. `#seed`.textContent = `JSON.stringify(S)`;
5. `'<!DOCTYPE html>\n' + clone.outerHTML` → `Blob` → `createObjectURL` → скрытый `<a download>` → `revokeObjectURL`;
6. имя файла `Вуокса-2026_<Имя>_09-авг.html`.

**Этот шаг 3 появился не случайно.** Среда, в которой файл собирался, дописывала в страницу свои
служебные скрипты (16 КБ) и стили (42 КБ); в скачанном файле они ломали загрузку до старта нашего кода —
пользователь видел белый экран на iPhone. Если будете менять `saveFile`, чистку не убирайте.
Дополнительно весь старт обёрнут в `try/catch`: при ошибке вместо белого экрана рисуется янтарная плашка
`.crash` с текстом ошибки.

`fetch(location.href)` использовать **нельзя** — по `file://` заблокировано в Chrome. Только клонирование живого DOM.

### Слияние чужого файла

`mergeInto(inc)` — общий механизм: им сливается и офлайн-файл, и состояние с сервера. `mergeFile(inc)` —
обёртка, которая ещё рисует тост. Сопоставление по `i` (id позиции):

* статус снаряжения — берётся более продвинутый (`Math.max`), если `ua` равны; если у входящего `ua` свежее — его значение;
* «куплено» — включается, если включено хотя бы у одного;
* тексты, цены, количества, владельцы, причины «не могу взять» — по более свежему `ua`;
* отсутствующие позиции добавляются с меткой `nw` («новое»);
* удалённые не воскресают: `forget()` пишет в `S.del` метку времени, и позиция возвращается,
  только если в чужом экземпляре её правили уже после удаления. «Отменить» в тосте вызывает `revive()`;
* участники: новые добавляются, остальные поля (имя, фото, права, ключ) — по `ua`; фотография
  подхватывается и без метки, если своей нет;
* общие блоки без собственных меток (логистика, меню, погода, лодка, подписи) — по `updatedAt` всего документа;
* итог — тост вида «Из файла Миши добавлено: 14 отметок, 3 новые позиции».

## Интерфейс

Один лендинг, шесть секций подряд: `s-home`, `s-crew`, `s-gear`, `s-buy`, `s-log`, `s-menu`.
Меню (снизу на телефоне, слева от 920 px) скроллит к секции и подсвечивает текущую по позиции скролла.
На телефоне панель прячется при скролле вниз и возвращается при скролле вверх.

Редактируется всё, «как вижу, так и правлю» (`contenteditable` + `edText()` / `edIn()`):
название и даты поездки, место, обложка (замена файлом), подписи денежных плиток, заголовки разделов,
примечания к вещам и продуктам, параметры логистики с единицами, подписи строк расчёта, карточка лодки,
канистры, этапы маршрута, вопросы «что уточнить», блюда и дни меню, имена и описания участников.
Добавление и удаление — везде, с тостом «Отменить» на 6 секунд.

### Производительность

Списки внутри закрытых аккордеонов **не строятся заранее** — `lazyBody(grp, body, build)` вешает построитель
на элемент, `toggleGrp` вызывает его при первом раскрытии. Это дало полную перерисовку 87 мс вместо 640 мс
и 2 136 узлов вместо 7 364. Если добавляете новые списки — используйте тот же приём.
`renderSec(id)` перерисовывает одну секцию вместо всей страницы.

## Ограничения, которые нельзя нарушать

1. Один файл `.html`, весь CSS и JS внутри. Ни одного `<link>`, `<script src>`, `@import`.
   Иконки — инлайн SVG, обводка 1,5 px, объект `I` в начале скрипта.
2. Ванильный ES5. Никаких ES-модулей (`type="module"` не работает по `file://`), никаких фреймворков и npm.
3. Мобильный приоритет, проектируется под 390 × 844. Интерактивные элементы не меньше 44 × 44 px.
   Горизонтального скролла нет нигде.
4. Всё на русском, с русской типографикой: кавычки-ёлочки, длинное тире, неразрывный пробел перед единицами.
   Ни одного английского слова в интерфейсе. Никаких `alert()` и `confirm()` — только свои шторки и тосты.
   Эмодзи как иконки не используются.
5. Имена участников: **Миша**, не «Мишка».
6. Не выдумывать позиции, которых нет в данных, и не выбрасывать существующие.
