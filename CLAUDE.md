# CLAUDE.md · Pine-to-Pine

Правила работы над этим проектом. Читать до первой правки, в каждой сессии.

## Что это

Лист планирования поездки для четверых. Заказчик — Максим, **не программист**.
Боевой адрес https://pine-to-pine.com (Cloudflare Pages, собирается сам при `git push`).
Код второй версии — в `app/` (React 19 + Vite + Tailwind 4 + shadcn/Radix + vaul + Motion).
Первая версия — `src/` + `build.js`, лежит в `v1/`, не трогать.

## Команды

```bash
node app/scripts/check-sums.mjs      # контрольные суммы, гонять после КАЖДОЙ правки расчётов
npx oxlint app/src                   # линтер
cd app && ./node_modules/.bin/tsc --noEmit -p tsconfig.app.json   # типы; npx tsc в корне НЕ работает
npm --prefix app run build           # сборка
npm --prefix app run build:offline   # офлайн-копия одним файлом
node publish-v2.mjs                  # разложить собранное по корню
```

Контрольные цифры, которые обязаны сходиться всегда: **330 км · 21 385 / 26 005 / 47 390 /
11 848 ₽ · 2 канистры**.

## Постулаты разработки

### 1. «Как вижу, так и редактирую»

Всё, что показано на экране, редактируется **на месте**, у того, у кого есть право.
Никаких «только для чтения без причины». Если поле видно и не правится — это дефект.

### 2. Правка на месте, а не в шторке

⚠️ Правило первой версии «список показывает — шторка редактирует» **ОТМЕНЕНО заказчиком
04.08.2026**. Шторки-попапы он забраковал: «мне не нужен поп-ап, в котором всё написано;
это прямо вот здесь, в этой таблице уже должно быть».

Значит: тап по названию — правка названия прямо в строке. Тап по количеству — счётчик
прямо в ячейке. Статус — кружок в ячейке. Удаление — действие в самой строке.
Шторка допустима только там, где иначе физически некуда деться (выбор фотографии,
календарь), и это надо обосновывать.

### 3. Ничего из данных не выбрасывать

Данные поездки — единственная ценность. Ни позиции, ни поля, ни чужие названия.
Если поле есть в документе, но не показано — это дефект (так потерялись `tileLabels`
и `secTitles`). Форму хранения не менять: слияние отдаёт такие поля целиком, и подмена
формы стирает их насовсем.

### 4. Молчаливых отказов не бывает

Если действие не сработало — человек должен прочитать словами, почему. Отказ прав,
отказ сервера, откат карты на другой движок, устаревшая ссылка. Молчание заказчик
читает как «сервис сломан» — и он прав.

### 5. Не положено — кнопки нет

Действие вне прав не рисуется вовсе. Серых кнопок и тостов-отказов не бывает.
Если действие положено, но не в этом месте — объяснить и дать альтернативу.

### 6. Премиальность — это сдержанность

Меньше деталей, а не больше. Единый ритм: сетка 8 px, шкала 12/13/15,5/20/24/32,
радиусы 4/8/12/16, три уровня теней. Подсказка объясняет **правило** («„Купить“
попадает в сумму»), но никогда не жест («тап по строке открывает карточку»).

### 7. Мобильный — первый

Проектировать под 390 × 844. Интерактив ≥ 44 × 44. Горизонтального скролла у страницы
нет (внутри блока — можно и нужно, как в таблице сборов). Десктоп — не растянутый мобильный.

### 8. Русский язык и типографика

«Ёлочки», длинное тире, неразрывный пробел перед единицами. Ни одного английского слова
в интерфейсе. Без `alert()` и `confirm()`. Эмодзи как иконки не используются.
**Миша, не «Мишка»** — даже если в таблице заказчика «МИШКА».

### 9. Бренд — ровно четыре цвета

Графит `#262513` · хвоя `#2B391A` · крем `#F9F3D4` · янтарь `#BC6C25`. Смеси можно,
новые цвета нельзя. Название сервиса набирается только шрифтом Chewy; в тёмной теме
слово — крем. Иконки — только lucide, одной толщины и одного размера в пределах блока.

### 10. Проверять, а не верить

Перед заявлением «работает» — прогнать проверки и показать вывод. В этой среде
**вкладка не рисует кадров**: скриншоты, `.gm-style`, анимации и измерения на узком
экране молча врут (эмуляция 390 px частично считает раскладку по реальному окну).
Геометрия — `getBoundingClientRect`, перекрытия — `elementFromPoint`, Radix кликать
`pointerdown` + `pointerup` + `click`.

## Чего ломать нельзя

* **Боевые данные.** Снимок строки `vuoksa2026` до работы; проверки только
  на `vuoksa2026-test`; тесты «запись в обход» НИКОГДА не на боевой строке;
  служебные строки называть только `*-test`; песочницу после работы удалять.
* `preview_start` открывает голый адрес — уводить только `location.replace(...)`
  на `http://localhost:5199/?u=Maks&k=zdzua343&sandbox=1`.
* Запись через `trip_write` в `lib/sync.ts` с откатом на прямую при 404; `isSandbox()`
  считает песочницей любой localhost.
* Модель прав (владелец/редактор/участник) и слияние `mergeInto` + `fillMissingKeys`.
* Формулы `lib/calc.ts` и контрольные суммы. `trip.dist.auto` не включать молча.
* `base` и `__BUILD__` в `app/vite.config.ts`; `sw.js?v=…`.
* Потолок высоты шторок задан **в одном месте** — `ui/drawer.tsx`; в `ResponsiveSheet`
  его возвращать нельзя (селектор с атрибутом сильнее класса).
* Правило в `index.css`, отбирающее нажатия у закрытой подложки и возвращающее их `body`.
  `!important` там обязателен: библиотека пишет `pointer-events` в inline-стиль.
* `S.tileLabels` — позиционный массив (0 транспорт, 1 продукты, 2 бюджет, 3 с каждого),
  не словарь. `S.secTitles` — объекты `{h, sub}` по ключам первой версии, где «Дорога»
  это `log` (карта ключей в `app/src/lib/sectitles.ts`).

## Как работать с заказчиком

Он не программист. Объяснять словами, что сделано и что нажать. Работать автономно,
вопросы задавать только там, где без ответа получится не то. Шаги в чужих кабинетах
(Supabase, Google Cloud) давать по одному действию за раз.

В конце каждой задачи давать: список изменённых файлов · какие проверки выполнены
(с выводом) · какие риски остались · что рекомендуется дальше · промпт следующей
сессии **текстом в чат**, а не только файлом.
