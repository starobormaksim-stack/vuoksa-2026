## ⛔ Первое, что надо усвоить: как не убить боевые данные

04.08.2026 боевую строку многократно затирали вкладки, открытые по «голому» адресу —
на компьютере (Chrome) и **на телефоне заказчика, во встроенном браузере Телеграма**.
Телефон нашёлся не сразу: с компьютера его не видно, а пишет он раз в полторы минуты.
Признак — цифры на экране заказчика не сходятся с контрольными (у него было
«11 855 ₽ / 215 позиций» против верных «11 848 ₽ / 216»). Механизм:
у такой вкладки в памяти СТАРАЯ копия листа, слияние (`mergeInto`) не воскрешает поля,
которых в ней нет, и на сервер уезжает обеднённый документ. Подробности — в `HANDOFF.md`.

Правила, без исключений:

* **Снять страховочный снимок ДО начала работы** и сохранить в песочницу сессии:
  `GET https://oagonfdnlgqkoosvgaly.supabase.co/rest/v1/trips?id=eq.vuoksa2026&select=data,updated_at,author`
  (заголовки `apikey` и `Authorization: Bearer` — anon-ключ лежит в `app/src/lib/supabase.ts`).
  Именно этот снимок спас данные в прошлый раз.
* **`preview_start` СНАЧАЛА открывает голый адрес и только потом переходит по ссылке.**
  Голый адрес = права владельца = запись в боевую строку. Поэтому порядок такой:
  сначала `preview_start({url: 'https://example.com'})` (нейтральная страница), потом
  `navigate` на приложение с `?sandbox=1`. Так же и с локальным сервером: поднять его,
  но вкладку сперва увести на нейтральный адрес.
* Локальный адрес — только `http://localhost:5199/?u=Maks&k=zdzua343&sandbox=1`.
  Агентам писать полный адрес с `sandbox=1` прямо в задании.
* **Перед правкой файлов проверить, не работает ли чужой сервер разработки**
  (`netstat -ano | grep :5199`): правка файла вызывает горячую перезагрузку ЧУЖОЙ вкладки,
  и та отправляет своё устаревшее состояние в базу.
* После проверок удалять строку песочницы `vuoksa2026-test`.
* Признак беды: у строки `vuoksa2026` пустой `author` при непустых данных.
* **Искать источник не только на этом компьютере.** Соединения с Supabase видно через
  `Get-NetTCPConnection` (процесс `chrome`), а окно с приложением — через
  `Get-Process chrome | Where MainWindowTitle` (заголовок «Вуокса · 2026 — Pine-to-Pine»).
  Но телефон так не найти: если записи продолжаются после закрытия всего на компьютере —
  спросить заказчика про телефон и Телеграм.

**Отдельная задача-минимум по этой теме** (не меняя модель прав): при загрузке, если серверный
документ новее локальной копии, брать серверный целиком, а не сливать со старой. Сейчас слияние
позволяет старой вкладке молча удалять поля. Настоящее лечение — задача 6 ниже.

## Задачи этой сессии

Заказчик перечислил их голосом 04.08.2026 после переезда. Порядок — от «проверить» к «переделать».

### 1. Шапка на мобильном: непрозрачная подложка над меню — САМОЕ ГЛАВНОЕ

Заказчик просит это уже третий этап подряд, дословно: «я тебе десять миллионов раз уже сказал…
у тебя по-прежнему оно как сквозное отверстие: входит и выходит с обратной стороны от этого
самого меню. Задник должен быть просто в цвет фона сайта».

Что видно на его снимке (iPhone, сайт открыт **в браузере внутри Телеграма**): над шапкой
с логотипом, в полосе системного статуса и адреса, просвечивает карта — содержимое страницы
проходит ПОД шапкой и вылезает сверху. Прошлая правка («непрозрачный фон под полоску
Телеграма») задачу не закрыла.

Что сделать: полоса над шапкой (область `env(safe-area-inset-top)`) должна быть залита
цветом фона сайта, полностью непрозрачной, без размытия и без полупрозрачности — и в светлой,
и в тёмной теме. Проверять **именно во встроенном браузере Телеграма на iOS**: там своя высота
безопасной зоны и свой порядок слоёв, обычный Safari эту беду не показывает.
Смотреть шапку в `app/src/App.tsx` и токены фона в `app/src/index.css`.

### 2. Свежая версия не доезжает до людей, и карта откатывается на OpenStreetMap

Со стороны сервера всё верно: выложена свежая сборка, ключ Google принимается,
`google.maps.Map` поднимается, мастер разметки на месте (проверено 04.08.2026 на живом домене).
Но **у заказчика на телефоне карта рисуется Leaflet/OpenStreetMap**, а жёсткая перезагрузка
на компьютере не помогла. Две отдельные болезни:

* **Старая версия держится в браузере.** Виноват служебный работник `app/public/sw.js` —
  он отдаёт закешированную оболочку и не обновляется. Заказчику нельзя объяснять про
  `Ctrl+Shift+R`: сайт обязан обновляться сам. Починить стратегию кеширования и добавить
  версию сборки в имя кеша.
* **Google отказывает во встроенном браузере Телеграма.** Вероятная причина: ключ ограничен
  по HTTP-referrer, а webview Телеграма может не отправлять `Referer` вовсе — тогда Google
  зовёт `gm_authFailure`, и приложение честно уходит на OpenStreetMap (это работает как задумано,
  см. `TripMap.tsx`). Проверить в консоли на телефоне; если подтвердится — либо добавить
  в список разрешённых пустой referrer нельзя, значит надо думать про ограничение ключа
  по-другому. **Ключ без ограничений в репозиторий не класть.**
* Заодно перевести `google.maps.Marker` на `AdvancedMarkerElement` (в консоли висит
  предупреждение об устаревании).

### 2. Строка поиска адреса у карты

«Было бы круто к карте ещё добавить строку поиска адреса, чтобы адрес искался, чтобы точку
можно было поставить». Прямой геокодер уже есть — `forwardPlace` и `placeQueries`
в `app/src/lib/geocode.ts`, работает через Google с откатом на Nominatim. Нужна строка над
картой: ввёл адрес — увидел находки — выбрал — карта наводится, точка ставится.
Правило «в строке списка нет полей ввода» здесь не нарушается: это не строка списка, а карта.

### 3. Свести карту, тайминг и маршрут в один блок

Сейчас карта живёт в «Поездке», а лента тайминга — в «Дороге», и заказчик считает это
разъездом одного и того же. Дословно: «тайминг и маршрут вместе совпадали… вот это вот,
которое у тебя есть, оно должно быть рядом с картой».

* Собрать один блок: слева (на десктопе) лента точек, справа карта; на мобильном — карта,
  под ней лента. Тап по точке в ленте наводит карту, тап по маркеру подсвечивает точку в ленте.
  Посредник для этого уже есть — `app/src/lib/mapfocus.ts`.
* **Разобраться с дублированием пробега.** Заказчик: «зачем-то в дороге дублируются, условно,
  30 км туда-обратно, бессмысленная история». Смотреть `trip.dist` (`src`/`auto`/`manual`/
  `kBack`/`local`) и `routeKm` в `app/src/lib/calc.ts`. **Осторожно: `dist.auto` не трогать** —
  переключатель «считать по карте» намеренно не сделан, он молча обнулит пробег до 30 км.
  Сначала понять, что именно заказчик видит дважды, и убрать повтор в подаче, а не в расчёте.
  Контрольные суммы (330 км) обязаны сойтись.

### 4. Обложка поездки и конечная точка на карте

«Слева информационная составляющая: обложка, даты поездки, которые из календаря подтягиваются,
конечная указывается. Там указывается Приозерское озеро Вуокса, и оно прям на карте тоже
указывается. Нажимаешь на карте на эту точку — указать конечную точку».

* Место поездки (`trip.places[]`, у главного `main: true`, координаты `61.04027, 30.13915`)
  должно быть видно на карте отдельной меткой, не такой, как точки маршрута.
* Конечную точку можно задать тапом по карте — как сейчас задаётся точка маршрута.
* Даты — из `trip.start` / `trip.end`. ⚠️ В снимке 10:00 `trip.end` был пустой; сейчас стоит
  `2026-08-14T18:00:00`. Проверить, что «10–14 августа» и обратный отсчёт считаются от этих полей.

### 5. Внешний вид — правки заказчика по списку

* **«Pine-to-Pine» набрать тёмно-зелёным** — цвет хвои `#2B391A` из брендбука. Единственное
  место, где живёт строка названия, — `app/src/components/Logo.tsx`, константа `BRAND`.
  Шрифт остаётся Chewy, другого не бывает.
* **Знак в шапке покрупнее.** Сейчас 26 px мобильный / 28 px десктоп — заказчик говорит,
  «почти ничего не рассмотреть». Раньше он же просил уменьшить со 100 px («слишком крупно,
  подумай о премиальном размере»), поэтому просто увеличить нельзя: нужно решение
  стилистическое. Разумный ход — не растить весь локап, а показать в шапке только эмблему
  крупнее (34–40 px), а слово оставить прежнего размера рядом.
* **Метки участников: кружки с подложкой.** «Пускай будут кружочки, но цвета пускай будут
  на подложке, чтобы их было лучше видно». Подложка обязана читаться и в светлой, и в тёмной
  теме. Сейчас люди различаются насыщенностью янтаря и формой метки (`toneOf` и `PersonMark`
  в `app/src/lib/people.ts` / `components/flops/`). Форму можно оставить только как запасной
  признак: заказчик просит именно кружки. Бренд по-прежнему четыре цвета, новых не заводить.
* **Кнопка «Добавить участника» слишком широкая.** «Отнимает очень много пространства…
  пускай будет маленькой, не во весь портрет». Сделать компактной, но цель касания
  не меньше 44 × 44.
* **Портреты обязаны быть квадратными.** Заказчик просил квадрат, а получаются прямоугольники.
  Сейчас участник кадрируется 3 : 4 (`PhotoSheet.tsx`, `usePhotoPick`). Поменять на 1 : 1
  и проверить, что уже загруженные фотографии не поедут.

### 6. Регистрация владельца через Supabase Auth (перенесено с прошлого этапа)

* владелец — единственный, кто регистрируется (Supabase Auth, magic link по почте);

* готовые экраны входа брать из shadcn-блоков. **Подходит `login-05`** — одно поле «почта»

## Чего ломать нельзя

* **Боевые данные** — см. раздел в начале файла. Это теперь главное правило проекта.
* Модель прав. Слияние правок по позициям (`mergeInto`, метки `ua`, `S.del`).
* Русский язык и типографика, без `alert()`/`confirm()`, эмодзи как иконки не используются,
  Миша — не «Мишка». Ничего из данных поездки не выбрасывать.
* Правила интерфейса из UX-проекта: список показывает — шторка редактирует (в строке нет
  полей ввода), никаких знаков `×`, `÷`, `=`, цели касания ≥ 44 × 44, строка списка ≥ 64 px,
  горизонтального скролла нет при 390 px.
* Бренд — ровно четыре цвета: графит `#262513`, хвоя `#2B391A`, крем `#F9F3D4`,
  янтарь `#BC6C25`. Все прочие оттенки — только их смеси. Название — только шрифтом Chewy.
* `base` в `app/vite.config.ts`: на Cloudflare `'/'`, везде ещё `'./'`. Жёсткое `'./'`
  ломает красивые адреса, жёсткое `'/'` ломает GitHub Pages и офлайн-копию.

## Как проверять и публиковать

```bash
node app/scripts/check-sums.mjs      # 330 км, 21 385 / 26 005 / 47 390 / 11 848 ₽, 2 канистры
npm --prefix app run build
npx oxlint app/src
```

Локальный запуск — конфиг `flops-app-dev` (порт 5199) или `flops-app-dev-alt` (5200)
из `.claude/launch.json`. **Вкладку сперва увести на нейтральный адрес, потом** открывать
`http://localhost:5199/?u=Maks&k=zdzua343&sandbox=1`.

Публикация теперь простая: **`git push` — и Cloudflare соберёт сам.**
Офлайн-файл и раскладка для GitHub Pages пока нужны, пока старый адрес живой:

```bash
npm --prefix app run build && npm --prefix app run build:offline && node publish-v2.mjs
git add -A && git commit -m "что поменялось" && git push
```

Проверить, что боевой адрес обновился:

```bash
curl -s https://pine-to-pine.com/ | grep -oE '/assets/index-[A-Za-z0-9_-]+\.js'
```

**Про проверки в браузере этой среды.** Вкладка не рисует кадры. Отсюда следует, что
НЕ работают и молча дают ложный результат: скриншоты, `IntersectionObserver`,
события `scroll`, `scrollIntoView({behavior:'smooth'})`, отрисовка Google Maps (`.gm-style`),
анимации ухода у шторок (узел остаётся в разметке с `data-state="closed"` — это не поломка).
Проверять надо иначе: геометрию — через `getBoundingClientRect()`, прокрутку — через
`behavior:'auto'`, обработчики прокрутки — рассылая `window.dispatchEvent(new Event('scroll'))`,
готовность Google — наличием конструкторов `google.maps.Map`. Клики по компонентам Radix
срабатывают через раз. Горячая перезагрузка Vite сбрасывает состояние компонентов —
после правки файла лучше перезагрузить страницу целиком.

## Многоагентная работа

Разрешена заказчиком. Что сработало: сначала своими руками общие помощники и паттерны
(`app/src/lib/people.ts`, `app/src/components/flops/`), затем агенты по непересекающимся
наборам файлов с точным перечислением API этих помощников, потом сборка и сверка руками.
Обязательно писать агентам, каких файлов НЕ касаться, и полный адрес с `sandbox=1`.
