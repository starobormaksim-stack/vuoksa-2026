  графит `#262513` (текст), хвоя `#2B391A` (фон тёмной темы), крем `#F9F3D4` (фон светлой),
  янтарь `#BC6C25` (акцент, глубокий `#A74612`). Вторичные тона логотипа: `#565237` и `#B1B499`.
  Все прочие оттенки — только смеси этих четырёх; песочный `#E4D0A5` и синий `#3E6B7A` выведены.
  Мелкий янтарный текст на креме даёт лишь 3.2:1 — для подписей брать `#8E3A0F`.
  Шрифт **Manrope везде** (вшит base64, `src/fonts-manrope.css`), Georgia убрана.

## Главная задача · доделать React-версию (`app/`) и опубликовать

Порядок работ. Основной документ — `docs/v2-ux-redesign.md`, оттуда берутся макеты и компоненты.

1. **Подключить shadcn/ui** по списку из раздела 5 UX-документа. Там же предупреждение:
   shadcn перезапишет существующий токен `--card`, его нужно переименовать в `--surface`,
   а переменные shadcn объявить алиасами.
2. **Разделы «Сборы» и «Закупка» по новому проекту.** Это то, чем заказчик недоволен больше
   всего: «в закупке какие-то формулы, всё криво и косо, пользоваться неудобно». Ключевое
   правило проекта: **список показывает, шторка редактирует** — внутри строки не должно быть
   ни одного поля ввода; тап по строке открывает карточку, тап по числу — экран правки одного
   числа с крупными −/+. Формулы вида `[2] [шт.] × [900 план] — [факт]` заменяются фразой
   «2 шт. по 900 ₽». В «Сборах» ряд чипов по четверым — полосой экипажа с одной фразой.
3. **Раздел «Дорога»** — отдельные пожелания заказчика от 04.08.2026, дословно:
   * сверху на десктопе **два квадрата рядом**: слева заглавная картинка, справа лист маршрута;
   * маршрут — **две вкладки: «Тайминг» и «Маршрут»** (можно предложить решение лучше,
     но и то и другое должно быть наверху, до денег);
   * на карте точки можно **ставить и передвигать**, подпись точки меняется соответственно;
     карта — та же, что на обложке (OSM); право менять — у владельца и редактора;
   * ниже — Техника, Топливо, Аренда, Расчёт, Канистры. Вся арифметика уже в `lib/calc.ts`,
     нужен только интерфейс; по UX-проекту расчёт показывается ступенями-фразами, а не таблицей.
4. **Экипаж и Меню** по UX-проекту.
5. **«Поездка»**: погода (день раскрывается гармошкой в строке, не шторкой), кольцо готовности
   из статусов «Сборов» (сейчас 0 %), права (сейчас даты меняет кто угодно — подключить `perms`
   из `useTrip()`).
6. **PWA + офлайн-сборка** одним файлом (`npx vite build --mode offline` настроена; фавиконку
   заинлайнить, для неё есть `src/emblem-*.svg`).
7. **Публикация.** Заказчик ждёт, что сможет тестировать вживую. Публиковать v2 вместо v1
   только после паритета и явного согласия заказчика.

Подключение к данным: `useTrip()` из `app/src/store.ts` отдаёт `{ S, update, remove, perms,
net, presence, isHere }`. Компоненты пока используют старый `useDoc()` — переводить на `useTrip()`.

## Чего ломать нельзя

* Боевые данные — строка `trips` с `id='vuoksa2026'`. Проверки — ТОЛЬКО с `?sandbox=1`
  (документ `vuoksa2026-test`), после проверок строку песочницы удалять.
* Офлайн на айфоне: приложение на экране «Домой» + скачиваемый самодостаточный файл; всё сетевое
  вырезается при сохранении (`SAVE_STRIP`). В офлайн-файле кнопки #bSave и #bMe остаются
  (в онлайне они скрыты стилем `#hdrTrim` — он вычищается при сохранении файла).
* Права по личным ссылкам; слияние правок по позициям (`mergeInto`, метки `ua`, `S.del`).
* Русский язык и типографика, без `alert()`/`confirm()`, эмодзи как иконки не используются,
  Миша — не «Мишка». Ничего из данных поездки не выбрасывать.
* Мобильный приоритет 390×844, интерактив ≥ 44×44, горизонтального скролла нет.
