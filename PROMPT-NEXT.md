## Как это делать (план, который уже согласован)

1. **Слой проекции `lib/spend.ts`** — `SpendRow.src` = имя коллекции-источника
   (`buy` · `rent` · `transport`), суммы берутся ТОЛЬКО из `lib/calc.ts`,
   своих записей в документ ноль. Экран собирается из проекции, данные лежат
   там же, где лежали.
2. ⛔ **Коллекции НЕ сливать.** `S.buy`, `S.transport`, `S.fuelPrices`, `S.rent`,
   `S.canRows` остаются каждая своей: метки удаления привязаны к имени коллекции
   (`del['rent:'+i]`), а слияние полей — к спискам в `merge.ts`. Меняется ЭКРАН,
   а не форма хранения (постулат 4).
3. **Порядок переезда:** сначала «Аренда» и «Логистика» подразделами внутри
   «Расходов» (`RoadCalc`/`RoadStrip` уже умеют рисовать блоки — переносится
   размещение, а не арифметика), потом «Проживание», потом уборка раздела
   «Дорога» из `SECTIONS`.
4. **В ТОМ ЖЕ коммите, где «Дорога» перестаёт быть разделом:**
   * `ADD_KINDS[].section` в `lib/addnew.ts` — с `'road'` на `'buy'` (иначе
     `goSection('road')` без якоря молча ничего не делает, `jump.ts` — постулат 5);
   * заявки поиска (`requestUnfold` / `jumpToItem`) для техники и аренды;
   * `LAST_MONEY_SECTION` в `sections.ts` — с `'stay'` на `'buy'`;
   * ключ `log` в `lib/sectitles.ts` (там лежит имя «Логистика», написанное
     первой версией, — оно должно остаться названием подраздела, У-160);
   * «Вопросы» отдельным разделом (`S.ideas`, сейчас в `RoadSection.tsx`).
5. **Взаиморасчёты** после переезда встают в конец «Расходов». ⚠️ Ни минуты
   раньше: пока «Логистика» стоит отдельным разделом ПОСЛЕ «Расходов», зачёт
   в конце «Расходов» снова покажет половину трат — за это заказчик ругал
   08.08.2026 (У-143).
6. Контрольные цифры (`node app/scripts/check-sums.mjs`) — после каждого шага.
   Каждый шаг — самостоятельно выкладываемый, после КАЖДОЙ выкладки — живая
   загрузка боевого.
