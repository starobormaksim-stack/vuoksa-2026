### 1. Единый лендинг вместо переключения разделов

Сейчас разделы — отдельные экраны: нажал «Сборы» — «Поездка» пропала. Заказчик хочет,
чтобы **вся страница была одним длинным лендингом**: разделы идут один за другим сверху вниз,
прокруткой. Меню (верхнее и нижнее) не подменяет содержимое, а **прокручивает к разделу**
и подсвечивает активный пункт по тому, что сейчас на экране.

* Все шесть разделов рендерятся одновременно, каждый в своей `<section id="…">`.
* Активный пункт меню определяется наблюдателем `IntersectionObserver` по видимой секции.
* Тап по пункту — плавная прокрутка к секции с учётом высоты прилипающей шапки
  (`scroll-margin-top`).
* Осторожно с производительностью: «Сборы» — 105 позиций, «Закупка» — 53. Ленивое тело групп
  (`Group`) уже есть, но проверь, что при одновременной отрисовке всех разделов страница
  не начинает тормозить на телефоне. Если тормозит — рисовать секцию, только когда она
  подошла к экрану, оставляя место заглушкой нужной высоты.
* Переход из поиска (`data-hit`, `jump` в `App.tsx`) должен продолжать работать.

### 2. Карта сразу после обложки, и не OSM, а Google

Заказчик: «сначала заглавная фотография, за ней сразу должна следовать карта».

* **Карта переезжает в раздел «Поездка»**, вторым блоком после обложки, и показывает
  построенный маршрут целиком.
* **Заменить OpenStreetMap на Google Maps** (бесплатный уровень). Сейчас `RouteMap.tsx`
  на Leaflet + тайлы OSM. Нужен ключ Google Maps JavaScript API — попроси его у заказчика
  или заведи через его аккаунт, если он даст доступ. Ключ в репозиторий не класть открытым
  текстом без ограничения по домену: у Google ключ ограничивается HTTP-referrer’ом
  (`pine-to-pine.com`, `starobormaksim-stack.github.io`) — так его публикация безопасна,
  и это штатный способ.
* **Постановка и перетаскивание точек сохраняются** (сейчас работают на Leaflet).
* **Новое: тап по адресу точки в «Тайминге» показывает её на карте.** Если у точки нет
  координат — открывается выбор места на карте, и после установки **название точки
  подставляется само** обратным геокодированием (Google Geocoding API), с возможностью
  исправить руками. Поле `addr` заполняется адресом, `n` — предложенным названием.
* В офлайн-файле карта по-прежнему честно пишет «Карта показывается в онлайне» и координаты.

### 6. Микроаналитика готовности

Заказчик: «чтобы индикатор показывал, насколько процентов тот или иной человек собран,
и цвета присваивались каждому из участников».

  Это то, чего сейчас нет: `readyOf`/`readyAll` в `app/src/lib/gearx.ts` считают проценты,

  (`app/src/components/trip/CrewReady.tsx`): сделать строки нажимаемыми.

### 7. Переезд на Cloudflare Pages, домен pine-to-pine.com и регистрация

Заказчик **зарегистрировал домен `pine-to-pine.com` через Cloudflare** и **согласился
на переезд с GitHub Pages на Cloudflare Pages**. Панель регистрации:
`https://dash.cloudflare.com/b1aaa7a020801b699cfbf3d3e896996c/domains/registrations/pine-to-pine.com`

**Как это делать (заказчик так попросил дословно).** В его аккаунт Cloudflare и Google
самому не заходить: пароли и коды доступа не вводятся ни при каких обстоятельствах.
Вместо этого **веди его по шагам**: одно действие — одно сообщение, куда зайти и что нажать,
и дожидайся, что получилось, прежде чем давать следующий шаг. Экраны описывай словами
(«слева в меню Workers & Pages», «кнопка Create application»), а не терминами из документации.
**Порядок шагов определяешь сам** — заказчик специально сказал, что ведущий здесь ты.

Разумный порядок (проверь, не изменилось ли что-то в интерфейсе Cloudflare):

1. **Cloudflare Pages вместо GitHub Pages.** Создать проект из того же репозитория
   `starobormaksim-stack/vuoksa-2026`. Сборка: команда `npm --prefix app run build`,
   каталог вывода `app/dist`. Тогда собранные файлы перестанут лежать в корне репозитория
   и `publish-v2.mjs` станет нужен только для офлайн-файла — это заметное упрощение.
   Пока переезд не завершён, GitHub Pages не отключать.
2. **Домен на проект.** Custom domain `pine-to-pine.com` и `www` — Cloudflare сам заводит
   записи, потому что домен зарегистрирован у него же. Сертификат выпускается сам.
3. **Красивые адреса** `pine-to-pine.com/<поездка>/<имя>`. На Cloudflare Pages это правила
   в файле `_redirects` (или `_routes.json`) в каталоге вывода: любой путь отдаёт `index.html`,
   а приложение само разбирает адрес. Сейчас личность и права читаются из `?u=<slug>&k=<ключ>`
   в `app/src/lib/perm.ts` (`readUrlUser`) — научи её понимать ещё и путь, СТАРЫЙ ФОРМАТ
   ОСТАВИТЬ рабочим: у людей уже разосланы ссылки.
4. **Ключ Google Maps** (для задачи 2). Тоже вести заказчика по шагам: Google Cloud Console →
   новый проект → включить Maps JavaScript API и Geocoding API → создать ключ →
   **обязательно ограничить его по HTTP-referrer** (`pine-to-pine.com/*`, `*.pages.dev/*`,
   `starobormaksim-stack.github.io/*`). С ограничением ключ можно спокойно держать в коде.
   Предупредить про биллинг: у Google карты бесплатны в пределах месячного лимита,
   но карту оплаты привязать всё равно попросят.

**Регистрация.** Заказчик просит не выдумывать своё, а взять готовое:

## Чего ломать нельзя

* **Боевые данные** — одна строка `trips` с `id='vuoksa2026'`. Проверки — ТОЛЬКО с `?sandbox=1`,
  после проверок строку `vuoksa2026-test` удалять.
  **Локальный адрес открывать сразу с `?sandbox=1`**: голый адрес без `?u=` даёт права
  владельца и пишет в боевую строку. В прошлую сессию так туда попали две тестовые записи
  (убраны, см. `HANDOFF.md`). Агентам, которые смотрят раздел вживую, писать полный адрес
  с `sandbox=1` прямо в задании.
* Модель прав. Слияние правок по позициям (`mergeInto`, метки `ua`, `S.del`).
* Русский язык и типографика, без `alert()`/`confirm()`, эмодзи как иконки не используются,
  Миша — не «Мишка». Ничего из данных поездки не выбрасывать.
* Правила интерфейса из UX-проекта: список показывает — шторка редактирует (в строке нет
  полей ввода), никаких знаков `×`, `÷`, `=`, цели касания ≥ 44 × 44, строка списка ≥ 64 px,
  горизонтального скролла нет при 390 px.
* Бренд — ровно четыре цвета, все прочие оттенки только их смеси. Название — только Chewy.

## Как проверять и публиковать

```bash
node app/scripts/check-sums.mjs      # 330 км, 21 385 / 26 005 / 47 390 / 11 848 ₽, 2 канистры
npm --prefix app run build
npx oxlint app/src
```

Локальный запуск — конфиг `flops-app-dev` (порт 5199) или `flops-app-dev-alt` (5200)
из `.claude/launch.json`; открывать `http://localhost:5199/?u=Maks&k=zdzua343&sandbox=1`.

Публикация:

```bash
npm --prefix app run build && npm --prefix app run build:offline && node publish-v2.mjs
git add -A && git commit -m "что поменялось" && git push
gh api repos/starobormaksim-stack/vuoksa-2026/pages/builds/latest --jq .status   # built
```

В этой среде вкладка браузера может не рисовать кадры: скриншоты не снимаются, а клики
по компонентам Radix (вкладки) срабатывают через раз. Внешний вид проверять вычисленными
стилями и геометрией элементов, поведение — вызовом функций напрямую.
