## Задача 3 — карта: этапы Э2…Э5 по плану архитектора

Полный план — в `HANDOFF.md`, запись от 05.08.2026. Коротко:

* **Э2. Развязать тон и штрих веток.** `toneAt()` (`marks.ts:71-75`) выдаёт тон и штрих
  связанной парой из пяти, своих пар четыре — **пятая техника получает тон и штрих
  первой, две ветки становятся неразличимы полностью**. Развязка `idx % 4` для тона и
  `Math.floor(idx/4) % 5` для штриха даёт 20 сочетаний при четырёх брендовых цветах.
  Проверять снятием: `filter: grayscale(1)` прямо в браузере (У-16).
* **Э3. Модель данных.** `Transport`: `crew` (Record id→число, форма как у `Gear.o`),
  `back`, `extraKm`, `ownKm`, `kmSrc`, `fare`. `RoutePoint`: `who`.
  ⛔ `owner` **остаётся и не переписывается** — `transport` сливается по позициям, подмена
  формы сотрёт данные у всех (У-04). Пустой `crew` читается как `{[owner]: 1}`.
  ⛔ Каждое новое поле обязано попасть в **три** места: `PLAIN.transport` или
  `PLAIN_JSON.transport` в `merge.ts:63-83`, вызов `jsonFields` в блоке route
  (`merge.ts:296-316` — сейчас его там нет вовсе), умолчание в `normalizeDoc`
  (`merge.ts:388-419`). Забыли строку — поле живёт в одном браузере и гаснет при первом
  слиянии. Тест слияния обязателен ДО показа заказчику.
* **Э4. Свой пробег техники.** Корень требования: `litres()` (`calc.ts:51`) для ВСЕХ
  авто берёт один общий `routeKm(S)`, две машины с разными маршрутами посчитать
  физически нельзя. Новая `transportKm(t, S)`, саму `routeKm` не трогать — на ней 330.
  Плюс `waterKm()` по гаверсинусу для лодки: OSRM зашит на профиль `driving`
  (`osrm.ts:42`) и про воду ответит чушью молча.
* **Э5. Кто платит.** Новая `shares(S)`, `perPerson()` не трогать — на ней 11 848.
  Инвариант `Σ shares === grandTotal` добавить **седьмой** строкой в `check-sums.mjs`,
  шесть существующих не трогать.

**Правило без исключений на всех этапах: пустое поле = сегодняшнее поведение.** Иначе
сдвинется 330 или 21 385.
