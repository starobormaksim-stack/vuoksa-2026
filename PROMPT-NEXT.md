### 2. ЖДЁТ ЗАКАЗЧИКА: проверить глазами то, что среда проверить не может

Вкладка в этой среде не рисует кадров. Проверено геометрией и чтением кода, глазами — нет:

* **Шапка во встроенном браузере Телеграма на iOS.** Третий заход; в коде `fixed` вместо
  `sticky` плюс распорка, непрозрачная полоса над шапкой, один `<meta name="theme-color">`,
  меняющийся с темой. Если «сквозное отверстие» осталось — причина не только в `sticky`.
* **Свежая версия доезжает сама?** Открыть сайт на телефоне, ничего не нажимая.
  Если карта на телефоне всё ещё OpenStreetMap при свежей версии — вот тогда разбираться
  с ключом Google (искать `gm_authFailure` в консоли телефона).
* **Метки Google, тап по метке, перетаскивание** на живом адресе.
* **Кнопка «Готово» в шторке аренды** на iPhone. На 390 px в этой среде помещается
  целиком с запасом 12 px — но iPhone единственная среда, где виден исходный дефект.
* **Блок «Поездки»**: на 390 px он высотой 3343 px (около четырёх экранов), на 1920 —
  1466 px. Горизонтального скролла нет ни там, ни там.
* **Восемь меток участников** — рисуются в 14 px, поле под узор ≈ 10 × 10 px. Различимы
  «на грани». Если мелко — увеличивать `size` в местах вызова `PersonMark`
  (`CrewSection`, `CrewReady`, `PersonSheet`, `ReadySheet`).
* **Мастер «Новая вещь»** — на шагах «название» и «сколько» тостов быть не должно,
  один тост в конце. Обычная правка вещи тост показывать обязана.

## Чего ломать нельзя

* **Боевые данные** — см. раздел в начале файла. Это главное правило проекта.
* Модель прав. Слияние правок по позициям (`mergeInto`, метки `ua`, `S.del`) и **страховку
  `fillMissingKeys`** в нём: она не даёт устаревшей вкладке терять поля.
* **`isSandbox()` в `app/src/lib/supabase.ts`** — то, что localhost считается песочницей.
  Это единственная защита от повторения происшествий 4 августа.
* **Запись через `trip_write`** в `lib/sync.ts` и откат на прямой путь при ответе 404:
  без отката приложение перестанет сохранять правки, пока SQL не применён.
* `trip.dist.auto` и формулы в `app/src/lib/calc.ts`. Контрольные суммы обязаны сходиться.
* Русский язык и типографика, без `alert()`/`confirm()`, эмодзи как иконки не используются,
  Миша — не «Мишка». Ничего из данных поездки не выбрасывать.
* Правила интерфейса: список показывает — шторка редактирует (в строке нет полей ввода),
  никаких знаков `×`, `÷`, `=`, цели касания ≥ 44 × 44, строка списка ≥ 64 px,
  горизонтального скролла нет при 390 px.
* Бренд — ровно четыре цвета: графит `#262513`, хвоя `#2B391A`, крем `#F9F3D4`,
  янтарь `#BC6C25`. Все прочие оттенки — только их смеси. Название — только шрифтом Chewy.
* `base` в `app/vite.config.ts`: на Cloudflare `'/'`, везде ещё `'./'`.
* **`__BUILD__`** в `vite.config.ts` и версия в адресе работника (`sw.js?v=…`): без них
  сайт снова перестанет обновляться сам.
* Разрезание сборки (`advancedChunks`) — только для онлайн-сборки. В офлайн-режиме
  `viteSingleFile` обязан сливать всё обратно в один файл.

## Как проверять и публиковать

```bash
node app/scripts/check-sums.mjs      # 330 км, 21 385 / 26 005 / 47 390 / 11 848 ₽, 2 канистры
npm --prefix app run build
npx oxlint app/src
```

⚠️ `npx tsc` в корне не работает — TypeScript установлен в `app/node_modules`:

```bash
cd app && ./node_modules/.bin/tsc --noEmit -p tsconfig.app.json
```

Локальный запуск — конфиг `flops-app-dev` (порт 5199) из `.claude/launch.json`.

Публикация: **`git push` — и Cloudflare соберёт сам.** Офлайн-файл и раскладка для GitHub
Pages нужны, пока старый адрес живой:

```bash
npm --prefix app run build && npm --prefix app run build:offline && node publish-v2.mjs
git add -A && git commit -m "что поменялось" && git push
```

Проверить, что боевой адрес обновился:

```bash
curl -s https://pine-to-pine.com/ | grep -oE '/assets/index-[A-Za-z0-9_-]+\.js'
```

**Про проверки в браузере этой среды.** Вкладка не рисует кадры. Не работают и молча дают
ложный результат: скриншоты, `IntersectionObserver`, события `scroll`,
`scrollIntoView({behavior:'smooth'})`, отрисовка тайлов карты (`.gm-style` не появляется,
хотя Google Maps загрузился), анимации появления и ухода у шторок (узел в разметке есть,
но остаётся сдвинутым за экран — это не поломка, считать координаты относительно самой
шторки). Проверять надо иначе: геометрию — через `getBoundingClientRect()`, зоны нажатия
и перекрытие — через `document.elementFromPoint()`, прокрутку — через `behavior:'auto'`,
готовность Google — наличием `window.google.maps` и подгруженных `marker.js`/`geocoder.js`.
Клики по компонентам Radix обычным `.click()` срабатывают через раз; надёжнее послать
`pointerdown` + `pointerup` + `click`. Шторка, открытая на одной ширине, при смене размера
окна **не перестраивается** — закрывать и открывать заново, иначе замеры врут.
