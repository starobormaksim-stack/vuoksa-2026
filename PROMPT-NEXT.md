## Ключевые решения (уже приняты, не переспрашивать)

* Сервис называется **FLOPS**. Название пишется ТОЛЬКО логотипом (`src/logo-light.svg` /
  `src/logo-dark.svg`), никогда текстом. Песочные элементы эмблемы заливаются цветом фона
  (CSS `[fill="#E4D0A5"]{fill:var(--bg)}`) — логотип «прозрачен» к заднику.
* Брендбук: светлая тема — фон ровно `#E4D0A5`, тёмная — ровно `#2B391B`,
  акценты `#BC6C25` / `#A74612` / `#161C10`. Шрифт **Manrope везде** (вшит base64,
  `src/fonts-manrope.css`), Georgia убрана.
* Решён **переход на React** (Vite + Tailwind + shadcn/ui и Aceternity как источники компонентов +
  Motion + Lucide + Leaflet/OSM, маршруты — публичный OSRM без ключа). Каркас в `app/`,
  данные уже мигрированы в `app/src/data/seed-v2.json` со сверкой сумм (`app/scripts/migrate.mjs`).
  Старая версия (`src/` + `build.js`) остаётся боевой до паритета. Ничего из v1 не удалять.
* Многоагентная работа (Agent/Workflow: продукт-архитектор, UX/UI-дизайнер через `frontend-design`,
  тестировщик) разрешена заказчиком на весь этап — переспрашивать не нужно.

## Задача 1 · Дизайн-ревизия текущей версии (сделать первой — заказчик видит косяки)

Пройти КАЖДЫЙ экран в ОБЕИХ темах и починить. Чек-лист заказчика дословно:
* чтобы тёмным по тёмному нигде не было написано;
* чтобы цвета соответствовали брендбуку;
* чтобы размеры соответствовали;
* чтобы ничего никуда не «ехало» (выравнивание);
* чтобы стилистика была полностью единой.

Особое внимание: легенда статусов «Сборов» в тёмной теме (иконки в кружках — цвет и выравнивание);
все зашитые цвета в CSS (`#E8A44A`, `#9CC3AF`, `#0E1F1A`, `rgba(247,241,230,…)` и т.п.) — они
подбирались под старые фоны, а фоны сменились на песочный/хвойный; контрасты текста.
Урок прошлой сессии: классы логотипа были `lgL/lgD` и конфликтовали с классом легенды `.lgD` —
теперь логотип `logoL/logoD`, легендовые `.lgD` не трогать и коллизии имён проверять.
Проверять на реальном рендере (скриншоты), а не только вычисленными стилями.

## Задача 3 · Сборка React-версии (`app/`)

По `docs/v2-architecture.md` и `docs/v2-design-system.md`, порядок:
1. Токены тем и каркас: верхнее прилипающее меню на десктопе (число разделов ДИНАМИЧЕСКОЕ —
   пользователи добавляют свои), нижняя панель на мобильном, логотип по правилам выше,
   шапка: присутствие · поиск · тема · «⋯». Тема — личная настройка браузера, НЕ поле документа.
2. «Поездка»: обложка (квадрат слева на десктопе, календарь дат, несколько точек назначения),
   готовность, деньги, погода (день раскрывается гармошкой в строке, не шторкой).
3. «Дорога»: карта Leaflet/OSM с точками маршрута (только в онлайне), Техника, Топливо, Аренда,
   Расчёт, Канистры — формулы из architecture-дока, суммы должны сходиться с контрольными
   (транспорт 21 385 ₽, закупка 26 005 ₽, итого 47 390 ₽, с каждого 11 848 ₽).
4. Синхронизация: портировать логику `src/online.js` (слияние по позициям, права по ссылке
   `?u=…&k=…`, Realtime через `trip_pings`, presence) — модель прав НЕ менять, владелец может всё.
5. PWA + офлайн-сборка одним файлом (`npx vite build --mode offline` уже настроена; фавиконку
   заинлайнить). Публиковать v2 вместо v1 только после паритета и явного согласия заказчика.

## Чего ломать нельзя

* Боевые данные — строка `trips` с `id='vuoksa2026'`. Проверки — ТОЛЬКО с `?sandbox=1`
  (документ `vuoksa2026-test`), после проверок строку песочницы удалять.
* Офлайн на айфоне: приложение на экране «Домой» + скачиваемый самодостаточный файл; всё сетевое
  вырезается при сохранении (`SAVE_STRIP`). В офлайн-файле кнопки #bSave и #bMe остаются
  (в онлайне они скрыты стилем `#hdrTrim` — он вычищается при сохранении файла).
* Права по личным ссылкам; слияние правок по позициям (`mergeInto`, метки `ua`, `S.del`).
* Русский язык и типографика, без `alert()`/`confirm()`, эмодзи как иконки не используются,
  Миша — не «Мишка». Ничего из данных поездки не выбрасывать.
* Мобильный приоритет 390×844, интерактив ≥ 44×44, горизонтального скролла нет.

  проверка: `gh api repos/starobormaksim-stack/vuoksa-2026/pages/builds/latest --jq .status` → `built`.

  если среда позволяет, иначе вычисленными стилями плюс геометрией элементов.
