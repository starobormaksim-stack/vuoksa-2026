## 1. Развилка, которую надо закрыть в первую очередь

Заказчик просит **shadcn/ui, Aceternity, Motion, иконки Lucide и карту**. Это прямо конфликтует
с зафиксированным в `README.md` ограничением: один HTML-файл, весь CSS и JS внутри, ванильный ES5,
ни одного `<link>` / `<script src>` / `@import`, без npm и фреймворков. На этом ограничении держится
рабочий офлайн на айфоне (приложение на экране «Домой» + скачиваемый самодостаточный файл).

**Разбор по каждой библиотеке — это не «нельзя», а «можно вот так»:**

| Что просит заказчик | Что реально делать |
|---|---|
| Иконки Lucide | **Можно полностью.** Lucide — это просто SVG-пути, лицензия ISC. Взять нужные иконки и вписать их в объект `I` в начале скрипта вместо нынешних самодельных. Никакой библиотеки не подключать. |
| Motion (анимации) | **Можно.** У motion.dev есть ванильный JS API (не React). Встроить минифицированный код инлайн (~20 КБ) в `src/app.template.html`. Альтернатива без единого килобайта — Web Animations API, он уже есть в браузере. Выбрать по результату, премиальность важнее «модности». |
| shadcn/ui, Aceternity | **Как код — нельзя**, это React-компоненты. Использовать как **источник дизайн-решений**: типографика, тени, радиусы, состояния, микровзаимодействия, композиция карточек. Воспроизводить своими средствами на ванили. |
| Карта | **Можно, но только в онлайн-версии.** Карта всегда требует интернета, поэтому она физически не может быть в офлайн-файле. В проекте уже есть механизм `SAVE_STRIP`, который вырезает всё сетевое при сохранении файла, — карта идёт туда же. |

**Про карту конкретно.** Заказчик сказал «google карту, которая позволит бесплатно, главное чтобы ты
это сделал». Google Maps бесплатным без карты оплаты не бывает: нужен API-ключ и включённый биллинг,
ключ пришлось бы положить в публичный HTML. Поэтому:

* **Тайлы карты** — OpenStreetMap, бесплатно и без ключа. Библиотека Leaflet (BSD-2) встраивается
  инлайн в `src/online.js`, чтобы не тянуть CDN.
* **Поиск места по названию и обратно** — Nominatim (OSM) либо уже используемый геокодер Open-Meteo.
* **Маршрут по дорогам с несколькими точками** — OSRM (публичный демо-сервер, без ключа) или
  GraphHopper / OpenRouteService с бесплатным ключом. Уточни у заказчика, готов ли он завести
  бесплатный ключ ради устойчивости; если нет — OSRM, но честно предупреди про отсутствие SLA.
* Если заказчик всё же хочет именно Google — ему нужно завести проект в Google Cloud и привязать
  карту. Спроси прямо, не решай за него.

**Рекомендация:** архитектуру не ломать, остаться на одном файле и ванили. Премиальность достигается
дизайном, а не React. Но это решение заказчика — **задай ему этот вопрос первым делом**, коротко и
по-человечески, и покажи таблицу выше.

## 2. Косяки, которые надо починить (проверено в коде, координаты точные)

1. **Бейджи налезают друг на друга.** На карточке экипажа `.crewChief` («владелец») и
   `.crewPhoto.isOn::before` («сейчас здесь») стоят в одной точке: у обоих `top:11px; left:11px;
   z-index:2`. Заказчик видит «поверх слова владелец ещё какая-то надпись». Развести и придумать
   внятную визуальную систему бейджей (роль / присутствие / это я).
2. **Карточки экипажа на десктопе мелкие.** Сейчас `@media (min-width:920px){.crew{grid-template-columns:repeat(4,1fr)}}`.
   Заказчик просит **по две карточки в ряд** — фотографии станут крупными. Заодно пересмотреть,
   что налезает на фото: градиент `.crewPhoto::after`, полоска `.cpBar`, подпись `.cpStat`
   («собрано X из Y»), кнопка ссылки `.cpLink`. Проинспектировать каждый элемент, чтобы фотографию
   не перекрывало и читалось адекватно.
3. **Контейнер лендинга узкий на десктопе.** `main{max-width:880px}` — заказчик просит шире.
   Подобрать так, чтобы на 1440–1920 было просторно, но строки текста не расползались.
4. **Дёргается анимация левого меню.** Гипотеза: `go(tab)` запускает плавную прокрутку через все
   разделы, а слушатель скролла по дороге переставляет `S.ui.tab` и дёргает `#navBar`
   (`transition: transform .3s, width .3s`) по каждому промежуточному разделу. Плюс `.view` при
   каждом `render()` заново проигрывает `slidein .28s`. Проверить и сделать переход спокойным:
   на время программной прокрутки подсветку не пересчитывать.
5. **Смена темы спрятана** в «⋯». Вынести наружу, в шапку или в левое меню, чтобы переключалось
   в один тап.

## 3. Что добавить · продукт

### 3.1. Обложка и название

* Сейчас слово «Вуокса» повторяется всюду. На обложке должно остаться: **название мероприятия**,

* **Даты привязать к календарю** — нормальный выбор дат, а не свободный текст. От дат считается
  обратный отсчёт и прогноз погоды (`S.trip.start`, `S.weather.days`).
* **Точка назначения связана с картой** (см. 3.2), точек может быть несколько.
* Название сервиса в шапке и в левом меню заказчик придумает и пришлёт отдельно. Сделай так, чтобы

  заглавными, везде остальное «Вуокса · 2026» — привести к одному написанию.

### 3.2. Карта и точки

* Место поездки выбирается **на карте**, а не вводится текстом.
* В логистике маршрут строится **точками на карте**: старт (сейчас «Дворцовая»), промежуточные
  остановки, финиш (Приозерск). Расстояние считается по маршруту с учётом всех точек и
  **автоматически подставляется в расчёт** вместо нынешнего ручного `log.dist`.
* Точки подписываются («выезд», «заправка», «спуск лодки») и складываются в раздел «Маршрут».
* Ручной ввод расстояния оставить как запасной вариант — карта может не ответить.

### 3.3. Погода по дням

* Тап по дню поездки — день **раскрывается шире, остальные отодвигаются** (гармошка), внутри
  подробный прогноз. Сейчас открывается шторка — заказчик хочет именно раскрытие в строке.
* Автообновление при появлении сети уже сделано (`weatherAuto()` в `src/online.js`) — проверить,
  что работает, и не сломать.

### 3.4. Количество и права на него

* Когда владелец (или любой, кто ставит задачу) назначает человеку вещь, он указывает количество.
* **Менять количество может тот, кто назначил, — не исполнитель.** Исполнитель может только
  **попросить изменить**. Механизм «не могу взять» с причиной уже есть (`gear.q`), логично
  расширить его до «прошу изменить количество» с указанием желаемого числа.
* Своё, добавленное самому себе, человек правит свободно.
* Права трогать осторожно: модель согласована с заказчиком, точки входа перечислены в `README.md`
  (`permOf` / `myPerm` / `isEditor` / `isChief` / `canEditItem` / `canMark` / `canEditPerson` /

## 5. Чего ломать нельзя

Полный список — в `README.md`, раздел «Ограничения». Ключевое:

1. **Офлайн на айфоне** — приложение на экране «Домой» плюс скачиваемый самодостаточный файл.
   Всё сетевое вырезается при сохранении через `SAVE_STRIP`. Карта, погода, синхронизация — туда же.
2. **Права по личным ссылкам** (`?u=…&k=…`), ключ в `S.people[].key`, ревокация при смене прав.
3. **Слияние правок по позициям** — сопоставление по `i`, метка `ua`, метки удалений `S.del`,
   условная запись по `updated_at`. Любое новое поле у позиции надо добавить в списки полей
   в `mergeInto`, иначе оно не будет синхронизироваться (так уже сделано для `as`).
4. **Русский язык и типографика**, без `alert()` и `confirm()`, эмодзи как иконки не используются.
   Имена участников: **Миша**, не «Мишка».
5. **Ничего из данных поездки не выбрасывать.**
6. Мобильный приоритет, проектирование под 390 × 844, горизонтального скролла нет.
   Интерактивные элементы не меньше 44 × 44 px — сейчас правило соблюдено только для нового,
   исторические кнопки внутри строк 38 px, кружок состояния 30 px. Это отдельная задача в `HANDOFF.md`,
   при редизайне её логично закрыть заодно.
