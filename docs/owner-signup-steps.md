# Вход владельца по почте — что нажать в Supabase

Пять шагов, по одному действию за раз. Порядок важен: **шаг 1 обязательно первым**,
иначе между шагом 2 и шагом 1 в лист сможет писать любой посторонний.

Кабинет: <https://supabase.com/dashboard> → проект `oagonfdnlgqkoosvgaly`.

---

## Шаг 1. Выполнить файл защиты

**Это первый шаг, и он не переставляется.** Пока он не сделан, включать регистрацию нельзя.

1. Слева в меню — **SQL Editor**.
2. Кнопка **New query**.
3. Открыть в проекте файл `docs/rls-apply-c.sql`, скопировать его **целиком** и вставить в окно.
4. Нажать **Run** (или Ctrl+Enter).

**Что должно получиться.** Внизу тремя табличками:

* `защита включена` — `true`;
* список политик: ровно две строки — `читать может любой` (SELECT) и `песочницу можно убирать` (DELETE).
  Строк со словами INSERT или UPDATE быть не должно;
* `колонка владельца есть` — `owner_email`.

Если вместо этого красная ошибка — ничего не включилось, файл можно запускать заново:
повторный запуск ничего не ломает.

---

## Шаг 2. Разрешить вход по почте

1. Слева — **Authentication**.
2. Пункт **Providers** → строка **Email**.
3. Включить два переключателя: **Enable Email provider** и **Enable Sign Ups**
   (второй как раз и разрешает заводить учётную запись первым письмом).
4. Убедиться, что включён **Magic Link** — вход идёт ссылкой из письма, пароля нет.
5. **Save**.

**Зачем.** Без «Enable Sign Ups» сервер отказывается заводить новый адрес, и сервис
честно скажет: «Регистрация по почте пока не включена».

---

## Шаг 3. Разрешить возврат на наши адреса

1. Там же в **Authentication** → **URL Configuration**.
2. В поле **Site URL** поставить `https://pine-to-pine.com`.
3. В списке **Redirect URLs** добавить три строки (кнопка **Add URL** на каждую):
   * `https://pine-to-pine.com/*`
   * `https://www.pine-to-pine.com/*`
   * `http://localhost:5199/*`
4. **Save**.

**Зачем.** Звёздочка на конце обязательна: без неё ссылка из письма вернёт вас
на главную вместо той страницы, с которой вы входили.

---

## Шаг 4. Своя почта для писем (можно отложить)

Встроенная почта Supabase шлёт всего несколько писем в час — на себя одного хватит,
на команду уже нет.

1. **Project Settings** → **Authentication** → раздел **SMTP Settings**.
2. Включить **Enable Custom SMTP** и вписать данные вашего почтового ящика
   (сервер, порт, логин, пароль, адрес отправителя).
3. **Save**.

Этот шаг можно сделать позже — вход работает и без него, просто с ограничением
на число писем.

---

## Шаг 5. Убрать служебную строку

От проверок защиты 4 августа в таблице осталась строка `probe-guard`. Вреда от неё
нет, но пусть будет чисто.

1. **SQL Editor** → **New query**.
2. Вставить одну строку и нажать **Run**:

```sql
delete from public.trips where id = 'probe-guard';
```

---

## Как проверить, что всё заработало

1. Открыть <https://pine-to-pine.com> по своей личной ссылке.
2. Меню «⋯» → **Вход владельца**.
3. Ввести свою почту → «Прислать ссылку».
4. Открыть письмо, нажать на ссылку — вернётесь в сервис уже вошедшим.

**Что происходит на сервере при первом входе.** Ваша почта записывается в лист как
почта владельца. Дальше письмом в этот лист сможете писать только вы: другой человек,
даже честно зарегистрировавшийся, получит отказ. Личные ссылки команды
(`?u=Kostya&k=…`) работают как работали — вход почтой у них ничего не отнимает.

⚠️ **Входите с того адреса, который считаете своим.** Первый вошедший закрепляется
за листом навсегда. Если ошиблись адресом — это чинится одной строкой в SQL Editor:

```sql
update public.trips set owner_email = null where id = 'vuoksa2026';
```

После неё владельцем снова станет тот, кто войдёт первым.
