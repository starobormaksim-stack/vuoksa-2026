# AGENTS.md · Pine-to-Pine — субагенты, роли и приёмка

Профили лежат в `.claude/agents/`. Каждый — отдельный файл с полями `name`,
`description` (условие срабатывания), `model`, `tools`.

⚠️ **Ростер — справочник, а не маршрут.** Гнать каждую правку по цепочке
«архитектор → исполнитель → тестировщик → рецензент» — это платить вчетверо за то же.
Маршрут выбирается по таблице ниже.

---

## Ростер

### Решают, что делать

| Профиль | Модель | Когда зовётся | Что отдаёт |
|---|---|---|---|
| **chief-architect** — главный архитектор | opus | правка трогает модель данных, слияние, права, синхронизацию, расчёты или сразу несколько разделов | план и вердикт, режет то, что ломает форму хранения |
| **product-architect** — продакт-архитектор | opus | до начала работы над требованием и перед словом «готово» | сверка со словами заказчика **дословно**, вердикт «принято / это не то» |
| **ux-designer** — проектировщик интерфейса | opus | до вёрстки раздела; заказчик сказал «неудобно», «криво и косо» | раскладка 390 и 1280, как правится каждое поле на месте |
| **bug-hunter** — диагност | opus | «сломано», причина неочевидна; две жалобы могут иметь один корень | диагноз `файл:строка` + механизм, **не правку** |

### Ищут готовое

| Профиль | Модель | Когда зовётся | Что отдаёт |
|---|---|---|---|
| **component-scout** — разведчик компонентов | sonnet | **до** того, как верстать любой новый элемент | конкретный компонент и путь из инвентаря / shadcn / Aceternity; запрет на велосипед |

### Делают

| Профиль | Модель | Зона файлов |
|---|---|---|
| **ui-implementer** | sonnet | `app/src/components/**` кроме `map/`, `App.tsx`, `sections.ts` |
| **core-implementer** | sonnet | `app/src/lib/**`, `store.ts`, `app/scripts/**` |
| **map-implementer** | sonnet | `components/map/**`, `lib/gmaps.ts`, `geocode.ts`, `osrm.ts`, `mapfocus.ts` |
| **design-system-keeper** | sonnet | `index.css`, `components/ui/**`, `theme.ts`, `Logo.tsx`, `fonts-chewy.css` |
| **copy-editor** | haiku | видимые тексты, подсказки, сообщения об отказах |

Зоны не пересекаются намеренно: два агента, правящих один файл параллельно, дают
конфликт, который потом никто не разберёт.

### Проверяют

| Профиль | Модель | Когда зовётся | Право |
|---|---|---|---|
| **live-tester** — тестировщик | opus | после любой правки интерфейса, **перед** словом «готово» | **вернуть работу** |
| **a11y-auditor** | sonnet | после правки цветов, размеров, органов; перед выкладкой раздела | вернуть по числам |
| **diff-reviewer** — состязательный рецензент | opus | дифф больше 200 строк или задет не один раздел | вернуть по пробелам |

### Обслуживают

| Профиль | Модель | Когда зовётся |
|---|---|---|
| **data-guard** — хранитель данных | sonnet | **первым** в любой сессии, трогающей данные, и после работы |
| **release-engineer** — выпускающий | sonnet | перед выкладкой; заказчик говорит, что видит старую версию |
| **lesson-keeper** — летописец | haiku | сразу после поломки, поправки заказчика или решения, о котором забудут |

## Маршруты по размеру задачи

| Задача | Маршрут |
|---|---|
| правка в одну строку, дифф описывается одним предложением | делаю сам, без агентов |
| правка одного раздела, до ~50 строк | `component-scout` (если что-то новое) → сам → `live-tester` |
| раздел целиком, новая функция | `ux-designer` → `component-scout` → исполнитель по зоне → `live-tester` → `product-architect` |
| трогает данные, права, слияние, расчёты | `data-guard` → `chief-architect` → `core-implementer` → `live-tester` |
| «сломано», причина неясна | `bug-hunter` → исполнитель по зоне → `live-tester` |
| дифф больше 200 строк | плюс `diff-reviewer` перед выкладкой |
| выкладка на боевой | `release-engineer` |
| любая сессия, где что-то сломалось | плюс `lesson-keeper` в конце |

**Кап: один субагент на подзадачу.** Параллелить можно только независимые зоны файлов.

## Правило приёмки

1. **Работа исполнителя не считается принятой, пока тестировщик не показал измерения.**
2. **Ни один агент не отчитывается «сделано» без вывода команд и замеров.**
   Отчёт без вывода — не отчёт.
3. **Отчёту субагента не верят на слово — сверяют с диффом.** Однажды субагент заявил,
   что починил чтение `tileLabels`, а на деле поменял форму хранения — это стёрло бы
   подписи заказчика насовсем (урок У-04, У-50).
4. **Тестировщик и рецензент не видят хода рассуждений исполнителя** — только дифф
   и критерии. Генератор и оценщик разделяются намеренно.
5. **Тестировщик имеет право вернуть работу.** Возврат — это нормальный исход, а не ЧП.

## Где субагент НЕ нужен

Anthropic дословно: *«do not use subagents to verify or double-check your own work»*
(документация «Prompting Claude Opus 5»).

Обычную правку я проверяю **сам** — командой (`tsc`, `oxlint`, `check-sums`) и замером.
Звать за этим агента значит платить вдвое за тот же ответ.

Субагент зовётся только туда, где **свежий контекст даёт то, чего у меня нет**:

* широкий аудит по многим файлам;
* крупный дифф, где я смещён в сторону кода, который сам написал;
* живой прогон интерфейса как человеком;
* спорный вердикт, где нужна независимая позиция;
* параллельное исследование независимых зон.

И где субагент прямо **вреден**: последовательная зависимая работа (второй шаг требует
полного вывода первого — дешевле в одной сессии), правки одного файла параллельно,
мелкие задачи, где накладные расходы делегирования больше выигрыша.

## Как ставится задача субагенту

Четыре обязательных элемента, иначе агенты дублируют работу и оставляют дыры:

1. **Цель** — что должно получиться, одной фразой.
2. **Формат ответа** — по образцу из его профиля.
3. **Инструменты и источники** — чем мерить, что читать, чего не открывать.
4. **Границы** — какие файлы его, какие нет, и чего не делать вовсе.

Каждый субагент начинает с **пустого контекста**: он не видит нашу переписку, не знает,
какие файлы уже прочитаны, и не помнит прошлых сессий. Всё, что ему нужно, кладётся
в задание или в его профиль.

⚠️ Много субагентов, каждый из которых возвращает подробный отчёт, **съедают контекст
быстрее, чем экономят**. Проси короткий структурированный ответ, а не пересказ работы.
