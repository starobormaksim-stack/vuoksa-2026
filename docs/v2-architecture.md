Кода здесь нет. Часть 1 — для заказчика, обычным языком. Часть 2 — для разработчика.

# Часть 1 · Для заказчика

## Что меняется по сути

Сегодня «Логистика» — это один жёсткий калькулятор: в нём намертво зашиты Honda, Aveo, лодочный
мотор и бензопила. Добавить катер или второй прицеп нельзя — нужно править код.

В v2 вместо зашитого калькулятора появляются **четыре простых списка**, которые вы наполняете сами:

| Список | Что в нём | Что он даёт |
|---|---|---|
| **Техника** | единицы транспорта: название, вид, топливо, расход, чьё | сколько литров нужно каждой единице |
| **Топливо** | справочник цен: АИ-95, АИ-92, дизель, своё | во сколько эти литры обойдутся |
| **Аренда** | лодка, парковка, место под лагерь, снаряжение | отдельная строка затрат, с транспортом не связана |
| **Точки маршрута** | точки на карте с подписями | расстояние, из которого считается бензин |

Деньги складываются из трёх источников: **топливо + аренда + закупка**. Ровно те же цифры,
что и сейчас, но теперь каждую строку видно и можно поменять без программиста.

## Разделы приложения

Вкладок остаётся шесть, как сейчас, — новые сущности живут внутри существующих разделов.

1. **Поездка** — обложка: название, короткое описание, **даты из календаря**, точки назначения
   (их может быть несколько), обратный отсчёт, погода, четыре денежные плитки, «вам поручено».
2. **Экипаж** — без изменений.
3. **Сборы** — как сейчас, плюс **свои разделы**: добавить, переименовать, удалить.
4. **Закупка** — как сейчас, плюс свои разделы и **единицы из списка** вместо ручного текста.
5. **Дорога** (бывшая «Логистика») — карта и точки, Техника, Топливо, Аренда, Расчёт, Канистры.
6. **Меню** — без изменений.

## Как это работает на примерах

**«Добавил катер → указал расход → топливо посчиталось само.»**
В «Технике» жмёте «Добавить единицу», пишете «Катер Yamaha», выбираете вид «катер», топливо
«АИ-95», расход «12 л/ч» и ставите 6 моточасов. В «Топливе» тут же появляется строка
«Катер Yamaha · 6 ч · 72 л · 5 076 ₽», а общий бюджет и «с каждого» пересчитываются.

**«Передвинул точку на карте → бензин пересчитался.»**
В «Дороге» точки маршрута лежат на карте: старт «Дворцовая», «Заправка», «Приозерск»,
«Спуск лодки». Расстояние по дорогам считается автоматически и подставляется в расчёт вместо
нынешних 150 км, введённых руками. Если карта не ответила — переключатель «считать вручную»
возвращает ручное число, ничего не ломается.

**«Взял лодку на 5 суток.»**
Аренда — свой список, к технике не привязан: «Лодка Ладога · 2 000 ₽ × 5 сут. = 10 000 ₽»,
«Парковка · 500 ₽ × 5 сут. × 2 машины = 5 000 ₽». Туда же ляжет место под лагерь или прокат
палатки — категория выбирается из списка.

**«Поручил Мише три пары носков.»**
Кто назначил — тот и меняет количество. Миша количество не правит, но у него есть кнопка
**«Попросить изменить»**: он ставит желаемое число и причину, вы видите просьбу в строке и
меняете одним тапом. То, что человек добавил себе сам, он правит свободно — как и раньше.

**«Не нравится "уп." — хочу "упаковки".»**
Единицы теперь выпадающий список (штуки, упаковки, пакеты, комплекты, пары, бутылки, банки,
кг, г, л, мл, порции) с пунктом «своё» — вписанное своё попадает в список и доступно всем.
Валюта — настройка документа, по умолчанию ₽.

## Что гарантированно не сломается

* **Цифры те же.** На текущих данных: транспорт 21 385 ₽, продукты 26 005 ₽, общий бюджет
  47 390 ₽, с каждого 11 848 ₽. Проверка построчно — в части 2.
* **Ничего из поездки не потеряется.** Каждое число и каждый комментарий из нынешней
  «Логистики» переезжает в конкретное новое поле — таблица переезда в части 2.
* **Совместная работа как сейчас.** Правки по-прежнему сливаются по позициям, а не «кто
  последний сохранил»; удалённое не воскресает.
* **Права не меняются.** Владелец, редактор, участник — как договорились. Добавлено ровно
  одно правило: количество меняет назначивший.
* **Удаление раздела безопасно.** Позиции не пропадают: они переезжают в группу
  «Без раздела», а «Отменить» возвращает раздел на место.

# Часть 2 · Техническая

## 2.1. Новые и изменённые сущности

Все новые коллекции — **массивы верхнего уровня** в `S`. Так они без переделок попадают в
существующий механизм слияния (`pick(<имя>)` сопоставляет по `i`, метки удалений — `S.del`).

### `S.transport[]` — единицы техники

```json
{
  "i": "tr_honda",
  "n": "Honda Accord",
  "kind": "car",
  "kindT": "",
  "fuel": "ai95",
  "rate": 10.5,
  "rateU": "l100km",
  "hours": 0,
  "litres": 0,
  "carry": false,
  "owner": "kos",
  "leg": "road",
  "calcT": "Бензин АИ-95 — Honda Accord (Костя)",
  "c": "",
  "nt": { "rate": { "t": "Расход Honda Accord (Костя), загруженная", "u": "л/100 км",
                    "c": "Смешанный цикл с багажом." } },
  "ord": 1, "by": "", "as": "", "ua": 0
}
```

| Поле | Смысл |
|---|---|
| `kind` | id вида из `S.kinds[]`; `kindT` — текст, если выбрано «свой вариант» |
| `fuel` | id строки из `S.fuelPrices[]` |
| `rate` / `rateU` | расход и его единица: `l100km`, `lh`, `fix` (фиксированный объём) |
| `hours` | моточасы — используются только при `rateU:"lh"` |
| `litres` | готовый объём в литрах — только при `rateU:"fix"` (бензопила, примус) |
| `carry` | `true` — топливо везём с собой в канистрах; `false` — заправляемся по дороге |
| `owner` | id человека из `S.people` |
| `leg` | какие участки маршрута проезжает: `road` / `water` / `walk` (для `rateU:"l100km"`) |
| `calcT` | подпись строки в расчёте; пусто — собирается автоматически |
| `nt` | подписи и примечания к числовым полям (прямая калька нынешних `logNotes`) |

### `S.fuelPrices[]` — справочник цен топлива

```json
{ "i": "ai95", "n": "АИ-95", "price": 70.5, "u": "₽/л",
  "c": "Средняя по сетевым АЗС Петербурга на 3 августа 2026.", "ord": 1, "ua": 0 }
```

Сид: `ai95`, `ai92`, `dt` (дизель, цена 0 — до первого использования не показывается).
«Своё» — обычная новая строка справочника.

### `S.rent[]` — аренда (отдельная категория затрат)

```json
{
  "i": "rn_boat",
  "n": "Лодка «Ладога»",
  "cat": "transport",
  "price": 2000, "unit": "сут.", "qty": 5, "count": 1,
  "calcT": "Аренда лодки «Ладога»",
  "c": "",
  "blocks": [
    { "t": "Аренда «Ладоги» на 5 суток, 10–14 августа",
      "c": "2 000 ₽ в сутки. Мотор 9,9 л.с. свой — везёт Костя." },
    { "t": "Входит в стоимость", "c": "4 спасательных жилета и 2 пары вёсел." }
  ],
  "warn": "Черпак в комплект не входит — попросить у хозяев на месте.",
  "nt": { "price": {…}, "qty": {…} },
  "ord": 1, "by": "", "as": "", "ua": 0
}
```

`cat` — id из `S.rentCats[]`: `transport`, `place` (место, кемпинг), `parking`, `gear`, `other`.
Сумма строки = `price × qty × count`. `count` по умолчанию 1 (парковка: 2 машины).
**С `transport[]` связи нет** — аренда самостоятельна, это требование заказчика.

### `S.route[]` — точки маршрута (расширение существующего массива)

Нынешние этапы маршрута уже являются точками с подписями и временем, поэтому новый массив
не заводим — расширяем существующий:

```json
{ "i": "r1", "n": "Сбор у Кости: Санкт-Петербург, Суздальский пр., 95",
  "time": "11:00", "c": "…", "done": false,
  "lat": 60.0369, "lon": 30.4022, "addr": "Суздальский пр., 95",
  "lab": "start", "labT": "", "mode": "road", "leg": 0, "legSrc": "", "ua": 0 }
```

| Поле | Смысл |
|---|---|
| `lat` / `lon` | координаты; пусто — точка не на карте (например, «Высадка, лагерь») |
| `lab` | подпись-метка: `start`, `drive`, `fuel`, `shop`, `launch`, `camp`, `finish`, `other` (+`labT`) |
| `mode` | чем идём до этой точки: `road` / `water` / `walk` — в бензин авто идут только `road` |
| `leg` | расстояние от предыдущей точки в км, пришедшее из OSRM |
| `legSrc` | `osrm` / `hand` — откуда взято |

### `S.trip` — даты, места, расстояние

```json
"trip": {
  "title": "Вуокса · 2026", "sub": "Юбилейная поездка · 10 лет",
  "start": "2026-08-10T07:30", "end": "2026-08-14T18:00",
  "dates": "10–14 августа 2026", "datesAuto": true,
  "places": [ { "i": "pl1", "n": "Приозерск · озеро Вуокса", "lat": 61.04, "lon": 30.14, "main": true } ],
  "route": "Санкт-Петербург (Дворцовая) → Приозерск → острова озера Вуокса · 5 дней / 4 ночи",
  "dist": { "src": "manual", "auto": 0, "manual": 150, "kBack": 2, "local": 30,
            "nt": { "manual": {…}, "kBack": {…}, "local": {…} } },
  "note": "…", "hero": "…"
}
```

* `start` / `end` — выбор из календаря; `dates` пересобирается автоматически при `datesAuto:true`,
  ручная правка текста ставит `datesAuto:false` (нынешнее поведение сохраняется).
* Число суток поездки = `end − start`, от него считается обратный отсчёт и длина прогноза.
  Суммы аренды на него **не завязаны** — `rent.qty` остаётся ручным, иначе цифры «поедут».
* `places[]` — точек назначения может быть несколько; погода берётся из точки с `main:true`
  (заменяет нынешние `trip.place` / `trip.lat` / `trip.lon`, старые поля остаются как запасные).
* `dist.src`: `auto` — расстояние из маршрута по карте, `manual` — ручное. Миграция ставит
  `manual`, поэтому цифры не меняются до первого построения маршрута.

### Справочники (пополняемые списки)

```json
"kinds":    [ { "i": "car", "t": "Автомобиль", "rateU": "l100km", "icon": "car", "ord": 1, "ua": 0 } ],
"units":    [ { "i": "sht", "t": "шт.", "full": "штуки", "ord": 1, "ua": 0 } ],
"rentCats": [ { "i": "transport", "t": "Транспорт", "ord": 1, "ua": 0 } ],
"rateUnits":[ { "i": "l100km", "t": "л/100 км", "per": "dist", "form": "per100" } ]
```

* `kinds` — автомобиль, катер, лодочный мотор, фургон, мотоцикл, самолёт, вертолёт,
  бензоинструмент, **свой вариант**. `rateU` в справочнике — единица расхода по умолчанию.
* `units` — штуки, упаковки, пакеты, комплекты, пары, бутылки, банки, кг, г, л, мл, порции
  плюс уже встречающиеся в данных `уп.`, `бут.`, `набор`.
* `rateUnits` — `l100km` (`per:"dist"`, `form:"per100"`), `lh` (`per:"time"`), `fix` (`per:"none"`),
  задел на `mi/gal`.

### Настройки документа

```json
"doc": { "cur": { "code": "RUB", "sign": "₽", "after": true },
         "distU": "km", "volU": "l", "canVol": 20 }
```

`rub()` заменяется на `money()`, берущий знак и позицию из `doc.cur`. `canVol` — объём канистры
(нынешние «канистр по 20 л»).

### Изменения в `gear[]` и `buy[]`

```json
"gear": { "…": "…", "o": { "mis": 2 }, "oby": { "mis": "max" },
          "q": { "mis": { "kind": "qty", "want": 3, "why": "Нужно на смену", "ua": 0 } } }
"buy":  { "…": "…", "q": 3, "qby": "max",
          "qask": { "by": "mis", "want": 5, "why": "На четверых мало", "ua": 0 } }
```

* `gear.oby[personId]` — **кто назначил** это количество этому человеку. Пусто — считается, что
  назначил `as`, иначе `by`, иначе никто (сид) → правит любой, у кого есть право на позицию.
* `gear.q[personId]` из строки становится объектом: `{ kind: "cant" | "qty", why, want, ua }`.
  Миграция: строка `"причина"` → `{ kind: "cant", why: "причина" }`. Чтение обеих форм
  обязательно — офлайн-файлы старого формата продолжают вливаться.
* `buy.qby` / `buy.qask` — то же самое для закупки, где количество одно на позицию.
* `buy.uid` — id единицы из `S.units[]`; текстовое `buy.u` остаётся и показывается, если `uid` пуст.
  Так старые данные читаются без конвертации.

### Секции становятся полноценными позициями

```json
"gearSections": [ { "i": "od", "t": "Одежда", "ord": 1, "by": "", "ua": 0 } ],
"buySections":  [ { "i": "alc", "t": "Алкоголь и сигареты", "personal": true, "ord": 6, "by": "", "ua": 0 } ]
```

Поле `id` переименовано в `i` (при чтении старого документа `id` копируется в `i`). Удаление —
через `forget('gearSections', i)`: позиции не трогаются, они попадают в виртуальную группу
«Без раздела» (`sec`, которого нет в списке). «Отменить» → `revive()` возвращает раздел,
позиции возвращаются в него сами, потому что их `sec` не менялся.

## 2.2. Формулы и проверка на текущих данных

### Расстояние

```
routeKm(mode) = (dist.src === 'auto' ? dist.auto : dist.manual) * dist.kBack + dist.local
dist.auto     = Σ route[].leg по точкам с mode === 'road'
```

Проверка: `150 × 2 + 30 = 330 км` — совпадает с нынешним `calc().km`.

### Топливо

```
litres(t) = rateU 'l100km' → routeKm(t.leg) * t.rate / 100
            rateU 'lh'     → t.hours * t.rate
            rateU 'fix'    → t.litres
fuelCost(t) = litres(t) * fuelPrices[t.fuel].price
топливо     = Σ fuelCost(t) по S.transport
```

| Единица | Вычисление | Литры | Рубли |
|---|---|---|---|
| Honda Accord, АИ-95, 10,5 л/100 км | 330 × 10,5 / 100 | 34,65 | 34,65 × 70,5 = **2 442,825** |
| Chevrolet Aveo, АИ-95, 8,5 л/100 км | 330 × 8,5 / 100 | 28,05 | 28,05 × 70,5 = **1 977,525** |
| Лодочный мотор 9,9 л.с., АИ-92, 2,5 л/ч | 10 ч × 2,5 | 25 | 25 × 65,5 = **1 637,5** |
| Бензопила, АИ-92, фикс. объём | 5 л | 5 | 5 × 65,5 = **327,5** |
| | | | **топливо = 6 385,35 ₽** |

### Аренда

```
rentSum(r) = r.price * r.qty * r.count
аренда     = Σ rentSum(r) по S.rent
```

| Строка | Вычисление | Итог |
|---|---|---|
| Лодка «Ладога» | 2 000 × 5 сут. × 1 | 10 000 |
| Парковка на базе | 500 × 5 сут. × 2 | 5 000 |
| | | **аренда = 15 000 ₽** |

### Итог

```
транспорт    = топливо + аренда                       = 6 385,35 + 15 000 = 21 385,35 → 21 385 ₽ ✔
закупка      = Σ q × (prf > 0 ? prf : pr) по buy со статусом 'buy' в неличных разделах = 26 005 ₽ ✔
общий бюджет = транспорт + закупка                    = 47 390,35 → 47 390 ₽ ✔
с каждого    = общий бюджет / S.people.length         = 47 390,35 / 4 = 11 847,59 → 11 848 ₽ ✔
личное       = Σ по личным разделам (алкоголь)        = 0 ₽ (цены не проставлены) ✔
```

Все четыре контрольные цифры воспроизводятся **точно**: формулы не переписаны, а разложены
по строкам — сумма слагаемых та же самая. Проверено расчётом по `src/seed.json`.

### Канистры

```
carryL(fuel) = Σ litres(t) по transport, где t.fuel === fuel и t.carry === true
cans(fuel)   = ceil(carryL(fuel) / doc.canVol)
```

Проверка: АИ-92 с `carry:true` — мотор 25 л + бензопила 5 л = 30 л → `ceil(30 / 20) = 2` канистры.
АИ-95 (`carry:false`) — 62,7 л, канистры не нужны. Совпадает с нынешним блоком «Канистры»,
включая сверку с количеством канистр в снаряжении (`g24`).

## 2.4. Правила слияния

Механизм не переписывается: `pick(<коллекция>)` сопоставляет по `i`, решает по `ua`, отсутствующие
позиции добавляет с меткой `nw`, удалённые не воскрешает благодаря `S.del`.

### Новые коллекции в `mergeInto`

| Коллекция | Поля, идущие в слияние (по более свежему `ua`) | Отдельные правила |
|---|---|---|
| `transport` | `n`, `kind`, `kindT`, `fuel`, `rate`, `rateU`, `hours`, `litres`, `carry`, `owner`, `leg`, `calcT`, `c`, `ord`, `by`, `as` | `nt` — сравнение через `JSON.stringify`, как `gear.o` |
| `rent` | `n`, `cat`, `price`, `unit`, `qty`, `count`, `calcT`, `c`, `warn`, `ord`, `by`, `as` | `blocks`, `nt` — по `JSON.stringify` |
| `fuelPrices` | `n`, `price`, `u`, `c`, `ord` | `nt` — по `JSON.stringify` |
| `gearSections` | `t`, `ord` | — |
| `buySections` | `t`, `personal`, `ord` | — |
| `units`, `kinds`, `rentCats` | `t`, `full`, `rateU`, `icon`, `ord` | справочники только пополняются; удаление — через `S.del`, уже использованное значение остаётся в позиции текстом |
| `canRows` | `t`, `c`, `fuel` | переводится из «общих блоков» в коллекцию с `i`/`ua` |

### Изменения в существующих правилах

* `route` — список полей расширяется: `['n','time','c','lat','lon','addr','lab','labT','mode','leg','legSrc']`.
  Флаг `done` сливается как сейчас (включается, если включён хоть у кого-то).
* `gear` — к списку `['n','c','sec','by','as']` добавляется сравнение `oby` через `JSON.stringify`
  (рядом с уже существующими `o` и `q`).
* `buy` — список расширяется: `['n','q','pr','prf','st','u','uid','who','sec','c','by','as','qby']`;
  `qask` сравнивается через `JSON.stringify` (просьба сохраняется, пока её не сняли).
* Блок «общее без собственных меток» (по `updatedAt` документа) теряет `log`, `boat`, `calcRows`,
  `canRows`, `logNotes`, `buySections` — они стали коллекциями. Остаются `menu`, `weather`,
  `tileLabels`, `secTitles`, `trip`, `theme`; добавляется `doc` (настройки валюты и единиц).
* `S.del` получает новые префиксы: `transport:`, `rent:`, `fuelPrices:`, `gearSections:`,
  `buySections:`, `units:`, `kinds:`, `rentCats:`, `canRows:`.

### Совместимость со старыми файлами

`migrate(S)` выполняется **и при загрузке своего документа, и при вливании чужого файла** (в
`mergeFile`, до `mergeInto`). Правило: если во входящем документе есть `log`/`boat`/`calcRows`,
он сначала переводится в новую форму, и только потом сливается. Так офлайн-копия, скачанная до
перехода на v2, продолжает вливаться без потерь.

## 2.5. Права на количество

Уровни `chief` / `editor` / `member` и точки входа (`permOf`, `myPerm`, `isEditor`, `isChief`,
`canEditItem`, `canMark`, `canEditPerson`, `canSetPerm`, `canSaveFile`) **не меняются**.
Добавляется одна функция поверх них:

```
assignerOf(item, person) = gear:  item.oby[person] || item.as || item.by
                           buy:   item.qby        || item.as || item.by

canEditQty(item, person) = assignerOf === S.ui.me            // назначил я
                        || (person === S.ui.me && assignerOf === S.ui.me)  // сам себе
                        || !assignerOf                        // ничей (позиция из сида)
                        || isChief()                          // владелец не ограничивается
```

* Исполнитель, у которого `assignerOf !== он сам`, вместо кнопок «−/+» видит **«Попросить
  изменить»**: шторка с желаемым числом и причиной → `gear.q[me] = {kind:"qty", want, why}`
  либо `buy.qask = {by:me, want, why}`.
* Назначивший видит просьбу в строке (тот же красный маркер `askRow`, что и у «не могу взять»)
  и меняет количество одним тапом — просьба снимается.
* Редактор сохраняет свои полномочия: если он одновременно исполнитель, действие доступно
  через «⋯ → изменить всё равно» — уровень прав не понижается, меняется только предлагаемое
  по умолчанию действие.
* Своё, добавленное себе (`oby[me] === me`), правится свободно — как сегодня.
* На данных сида `oby` пуст, а `by` пуст у всех позиций, поэтому поведение до первого назначения
  ровно такое же, как сейчас: никаких новых запретов задним числом.

## 2.6. Что остаётся открытым

1. **Число суток** живёт в трёх местах: даты поездки, `rent.qty` аренды, длина прогноза погоды.
   Связывать их автоматически рискованно (аренда может начинаться не в день выезда), поэтому
   предлагается подсказка «в поездке 5 суток — подставить?» рядом с полем, а не автоподстановка.
2. **Расход в «л/ч» и маршрут** не связаны: моточасы вводятся руками. Автоматики по воде
   (длина водного участка ÷ скорость) в этой версии нет — при желании считается позже из
   `route[].mode === "water"`.
3. **Курс валюты** не вводим: `doc.cur` меняет только знак и формат, пересчёта сумм нет.
4. **Чистка `S.del`** становится актуальнее — префиксов стало больше (задача из `HANDOFF.md`).
